# X 与 YouTube 平台下载

Tessera 在已有下载队列中增加 X 单帖图片、视频，以及 YouTube 单视频、Shorts 的下载。解析、清晰度选择、Cookie 导入、进度与任务控制沿用同一个界面。

常见链接失败的实现缺陷、HLS 扩展、同清晰度重试与当前验证结果见 [离线下载兼容性排查](offline-reliability.md)。

## 使用和部署

- 「下载任务 → 添加下载」粘贴平台链接，每次一个帖子或视频。X 的媒体逐项选择，YouTube 同一个视频只选一个清晰度。文件直链仍可每行一个。
- 「平台登录 Cookie」可粘贴 Cookie 请求头（大小写均可）或导入 Netscape cookies.txt，最多 32 KiB、128 个对应平台 Cookie。域、路径、有效期与 HTTPS 限制保留；旧 twitter.com 根域 Cookie 适配到 x.com。无需从服务器读取桌面浏览器，也不执行粘贴的命令。
- 管理端「系统设置 → 下载与资源」分别启用 X、YouTube，配置清晰度和单任务大小上限。默认 720p、512 MiB，低资源预算最多 720p、512 MiB；小容器实际下载并发为 1。解析子进程全局最多一个；复用解析结果的平台任务可按并发设置同时下载，YouTube 和 M3U8 共用一个视频处理名额。
- 默认轻量／FFmpeg 镜像保持原用途，平台功能使用新构建目标：

```bash
docker build --target platform -t tgdrive:platform .
```

本地开发安装 `pip install -e '.[platform]'`，另需 FFmpeg、Node.js 22+ 或 Deno 2.3+。启动开关为 `--offline-x`、`--offline-youtube`，上限为 `--offline-max-mib`、`--youtube-max-height`，环境变量见 README 和管理员文档。管理员已有配置优先，不自动替管理员改开关。

标签发布工作流仍只由 `v*` 触发，新增同版本 `-platform` 和 `latest-platform` 标签；这些标签在对应版本实际发布后才可拉取。本轮只构建本地验证镜像，没有发布或替换部署。

## 执行与数据边界

gallery-dl、yt-dlp、配套 EJS 固定在 `pyproject.toml` 的可选依赖中。解析器按需启动为子进程，全局最多一个，等待名额和解析合计最多 120 秒。取消时回收整个进程组，包括 JavaScript 子进程；Node 堆上限为 128 MiB，禁用核心转储，不加载额外插件或远端 EJS 组件。gallery-dl 仅使用内存缓存。

解析库 HTTP 请求经标准输入输出协议交给主进程。每次请求和重定向限定平台及媒体 HTTPS 域名；直连时再校验并固定公网 IP，配置出站代理时由代理解析域名（见下文“出站代理”）；最多 100 个请求，每个解析响应最多 8 MiB。保留多个 Set-Cookie，Cookie 按域和路径发送。媒体请求只保留非认证播放头，允许这些头在受限的平台 CDN 间跳转；不将登录 Cookie、认证头发送到媒体 CDN。直连时服务器 DNS 返回 fake-IP／保留地址会被拒绝。解析请求遇到连接重置、超时会整体重发，最多 3 次。

YouTube 的 https 格式由 yt-dlp 标注 `http_chunk_size`（10 MiB）。googlevideo 会把不分段的整文件请求限速到接近播放速度，所以媒体轨按该大小逐段发送 Range 请求，每段核对 `Content-Range` 起止与总长度；来源忽略 Range 返回 200 时按整文件读取。X 等未标注分段的媒体仍一次读取。

解析时取得的媒体地址随任务加密保存，在有效期内（X 24 小时，YouTube 3 小时且早于地址自带的 expire 10 分钟）直接下载；过期或来源返回 401／403／404／410 时重新解析一次，按已选媒体编号和清晰度匹配，不自动降低清晰度。平台任务不拼接旧分片，停止后重新开始从头下载。网络中断、超时及 HTTP 408／425／429／5xx 会自动重试 3 次，分别等待 10、30、90 秒，任务显示“等待恢复”和重试次数；文件直链从已保存的 16 MiB 分段续传，YouTube 分段读取在任务内原地续读。POST、认证失败、内容变化不自动重试。状态显示解析来源、下载媒体、合并音视频、完成保存；合并和保存时不显示过期网络速度。

X 原图、MP4 和 YouTube 已合并的 MP4 流式进入分片加密存储。YouTube 分离轨先保存到数据目录 `offline-cache/task-*`，目录 0700、文件 0600；大小受单任务上限和磁盘保留空间限制。FFmpeg 仅读取受控本地文件、复制编码数据，MP4 输出直接进入加密存储，复用上传指纹，不另存完整成品临时文件。中断、失败回收临时轨和未完成分片；重启清理上次异常退出的任务缓存。临时轨为明文，需为输入轨和最终本地加密文件同时预留磁盘空间。

schema v15 只给已有任务表追加平台、处理阶段字段；迁移前沿用元数据库备份，不重建表或删除旧记录。所有来源参数、Cookie、解析选择继续保存在原有加密任务字段中，随加密口令轮换重新加密。任务列表与审计不包含这些凭据。

内存保护读取同一 cgroup 的限额和用量，扣除可回收的闲置文件缓存，避免顺序写临时轨导致反复中断；临时内存盘仍计入用量。资源保护和取消不会依赖浏览器保持打开。

## 支持限制

解析器的异常按真人验证、登录、地区、Cookie、请求频率、JavaScript 挑战和组件异常分类。挑战失败进一步区分内存不足、组件不匹配、运行进程异常、播放器脚本读取和解码器错误；不能只凭通用挑战提示认定 Cookie 无效或版本不匹配。未知异常在界面附带异常类型；容器日志中的 `platform_extract_failed` 记录固定分类、异常类型、代码位置、`js_reason`、`js_retries` 和最近最多 16 次请求的固定阶段／状态码，Cookie 与认证头仅记录是否存在，不输出原始异常文本、完整 URL 或凭据。`platform_source_failed` 标识解析通道的连接失败。YouTube 只列举格式，不提前试下载默认媒体；网页／播放 API／播放列表的解析 403 与任务中的媒体 403 分开提示。Docker 中使用这些改动需要重新构建平台镜像；依赖版本齐全不能保证单个视频必然可下载。

Node 默认堆上限仍为 128 MiB；只在明确的堆内存不足时提高到 192 MiB 重试一次。登录客户端的挑战无法解码时尝试一次不带账号 Cookie 的公开客户端，只有公开访问确实返回媒体时才使用结果；登录／私密／年龄限制不触发此回退。所有尝试共用 120 秒总时限和最多 100 次受控请求，不动态联网下载 EJS、不改变清晰度选择或访问权限。恢复成功时日志记录 `platform_extract_recovered` 和固定的重试标记；仍失败时保留原登录请求的原因。

- YouTube 展示当前实际可用的 HTTPS／HLS H.264／AAC MP4 清晰度，支持音视频分离后合并；另提供「仅音频 · M4A」（HTTPS AAC 单轨不经 FFmpeg，HLS 音频经 FFmpeg 封装）。登录后也尝试 Safari HLS，HTTPS 媒体拒绝后按同清晰度优先重解析 HLS。X 文件名为 `作者-帖子ID-序号`。暂不支持直播、预告、仍在处理的视频、频道／播放列表批量下载、DRM、WebM／AV1 或额外 PO Token 提供器。
- X 仅处理单条帖子中的原图与视频，不抓取主页、回复、引用帖或外部卡片。
- 平台可能要求 Cookie、限制服务器出口或暂时不提供格式；普通 Cookie 不保证所有视频可下载。接口变化时需更新成对的解析依赖并重建镜像，不能长期保证所有链接有效。
- 真实登录 Cookie 的成功率未验证；未登录的公开帖子与视频已经过出站代理实测（见“出站代理”）。

## 出站代理

管理员在「系统设置 → 下载与资源」填写出站代理，或用 `--offline-proxy` / `TGDRIVE_OFFLINE_PROXY` 提供启动默认值。支持 `http://`（CONNECT 隧道，HTTP 来源也走隧道）与 `socks5://`／`socks5h://`（均把域名交给代理解析），可带用户名和密码；地址规范化后保存在 `settings` 表，控制台和接口只回显 `******`，提交占位符表示保留原密码，审计只记录 `proxy_enabled`。

启用后，HTTP 直链、M3U8、平台解析子进程的全部请求和媒体下载都经代理，连接前不在本地解析 DNS。由于无法固定 IP，只拒绝字面内网／保留 IP（含 IPv4 映射与转换前缀）、`localhost`、无点主机名、`2130706433`／`0x7f.1` 这类数字主机名，以及 `.local`、`.localhost`、`.lan`、`.internal`、`.home.arpa`、`.intranet`、`.corp`、`.localdomain` 后缀。代理自身可以位于本机或内网。这一取舍由管理员显式开启，适用于服务器只能经代理出网的部署。

建立连接阶段（代理握手、TLS 握手、直连）出现重置或超时属于 `TransientError`，自动重试 3 次；代理返回 502／503／504 或 SOCKS5 一般失败、网络／主机不可达、TTL 过期同样可重试。407 认证失败、证书校验失败等不重试。

实测（2026-10-12，本机 Clash `127.0.0.1:7890`，Fake-IP DNS）：YouTube 单视频解析 6 个 H.264 清晰度，约 17 秒；同一媒体轨分段读取 1.40 MiB/s，不分段 0.73 MiB/s。网页提交 360p（音视频分离）后经历解析、下载、合并、保存，约 30 秒完成，成品 28558685 字节，FFmpeg 完整解码通过（10:34，H.264 640×360 + AAC）。X 公开视频帖无需 Cookie，20.2 MiB 约 3 秒完成。代理偶发 TLS 握手重置，已由连接重试覆盖。

## 自动重试与解析复用（2026-10-12）

- 实测（同一代理环境）：YouTube 360p 与 X 视频同时提交，两个任务开始后 0.2 秒都进入下载阶段，期间没有再启动解析子进程，约 11 秒全部完成；此前每个任务开始时都要重新解析 10–17 秒，并且平台任务只能逐个执行。
- 每个 64 KiB 数据块的账号／锁定检查改为最多每 0.5 秒查一次库，限速配置每秒读取一次：本机 20000 块（约 1.2 GiB）从 119 ms 降到 3 ms。禁用账号和锁定系统仍通过直接取消任务立即生效。
- 回归覆盖：地址失效后重新解析一次、网络失败自动重试直到成功／用尽后标记失败、直链 503 后保留 16 MiB 断点续传、YouTube 分段读取中途断开后从准确位置续读。

## 体验补充（2026-10-12）

- YouTube「仅音频 · M4A」：选择解析结果中码率最高的 AAC 音轨，按 10 MiB 分段读取，不经 FFmpeg。实测 10:34 音轨 10271496 字节，完整解码通过。

- 已完成任务显示累计用时和平均速度（schema v16 追加 `offline_tasks.elapsed_seconds`，只累计实际运行时间，重新下载或更新参数时清零）；直链地址缺少扩展名时按 Content-Type 补全，例如百度图片 `/it/u=…&fm=3028` 保存为 `.webp`。
- 管理端显示解析组件、JavaScript 运行时与 FFmpeg 的版本，yt-dlp 超过 60 天提示更新镜像。
