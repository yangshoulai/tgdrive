# 缩略图处理流程

自动生成支持图片、视频、音频内嵌封面，不处理 PDF、Office、SVG 或系统区助手附件；任何文件（含上述类型）都可以由用户在文件菜单设置自定义缩略图。首要约束是减少原文件的重复传输。

| 场景 | 处理方式 | 额外读取原文件 |
| --- | --- | --- |
| 网页上传 | 浏览器使用本地 File，后台等待上传端 | 无 |
| 浏览目录、搜索、网格、滚动 | 只加载已有缩略图，缺图显示类型图标 | 无 |
| 图片预览 | 直接缩放已经加载的原图 | 无 |
| 视频预览 | 只截取通过画面质量检查的当前已解码画面，不因播放时长放行，不跳转、不另建播放器 | 无 |
| 音频预览 | 原生播放器不向网页开放缓冲字节，后台复用实际交付的数据提取封面 | 无 |
| 服务端自动队列 | 复用上传、下载任务、真实预览已收到的密文缓存，不足就等待；完全没有数据的任务不入队 | 无 |
| 复制、秒传、保存他人分享 | 同一 Blob 已有缩略图直接复用；没有时等文件被实际读取 | 无 |
| 文件菜单「设置／更新缩略图」（任何文件） | 用户上传本地图片或填写图片地址，浏览器缩放后保存 | 无（只读取用户提供的图片） |
| 播放器「将当前画面设为缩略图」 | 固定当前已解码帧后保存 | 无 |

文件助手的生成卡片仍需用户点击，点击后逐个提交手动生成请求（`POST /thumbnail/generate`）（队列满时等待再提交），由服务器优先用缓存、按预算回源，不在浏览器下载原文件——服务器取存储是入站流量，浏览器下载则多一份出站流量。只有服务器没有 FFmpeg 时，卡片才退回浏览器读取文件生成。

## 图片与失败状态

`none` 是数据库里的“曾尝试但未生成”标记，用于停止自动重复处理，不是一张图片。网页会话接口（普通与私密的列表、搜索、详情、`/thumbnail/status`）、下载任务关联文件及公开分享的 `thumbnails` 只包含实际图片规格 `thumb`、`grid`、`poster`，`thumbnail_versions` 也只包含这些图片的版本。

网页字段 `thumbnail_status` 表达已有结果：`missing` 表示尚无记录，`ready` 表示有实际图片，`unavailable` 表示只有失败标记。失败时返回 `has_thumbnail: false`、`thumbnails: []`、`thumbnail_versions: {}`；这不表示文件已有缩略图，也不禁止用户显式重试。浏览器用独立状态停止对已确定失败的文件继续轮询或自动截帧，不再用数组非空判断失败状态。访问密钥 `/api/v1/list` 保留既有 `none` 数组语义，以维持程序接口兼容。

用户通过助手明确补图时，`ui_generate_thumbnails` 默认也选择仅有 `none` 的文件；`regenerate` 只控制是否补做已有小图但缺网格图的旧缩略图。工具结果分别报告已有图片、需要生成和曾经失败的数量。卡片条目的 `retry` 标志让无 FFmpeg 时的浏览器退路能够取得覆盖旧失败标记的生成权；保存仍复核原文件版本与票据。该选择不清除数据库标记，也不自行执行生成。

## 职责划分

| 角色 | 负责 | 不做 |
| --- | --- | --- |
| 上传页 | 用本地 File 生成三种规格并保存 | 不等待后台、不重复读取已上传数据 |
| 预览页 | 图片用已加载原图、视频用已解码画面 | 不为截图另开请求、不跳转播放进度 |
| 后台队列 | 音频封面、S3／访问密钥／离线下载写入的文件、浏览器超时或失败的接管、手动生成 | 即时自动任务不回源 |
| 自动补图 | 写入 10 分钟后仍缺图的文件，按单文件预算与每日额度从存储读取 | 不产生出站流量；不重试已确定无法生成的文件 |
| 管理员 | 在「安全与维护」查看匿名队列 | 看不到文件名、路径、账号 |

## 自定义缩略图

服务器准备视频候选画面供用户挑选的流程已移除（`video_candidates.py`、`/thumbnail/candidates*`、`thumbnails.candidates` 设置均删除，旧设置值留在 settings 表中不再读取）。上传、本地文件生成、预览补图、后台自动补图和助手批量生成沿用原流程；用户对结果不满意时自行指定图片。

- 入口：文件菜单「设置缩略图」（尚无缩略图）／「更新缩略图」，普通与私密空间共用 `user/thumbnail-editor.tsx`，适用于所有文件类型。
- 图片来源：本地图片（选择、拖入或粘贴，≤20 MB），或图片地址。地址由 `POST /thumbnail/fetch {url}` 交给服务器读取：只接受 http(s)，经离线下载的 `SafeHttpClient`（拒绝内网地址、遵循管理员出站代理，不转发任何登录凭据），30 秒超时，最多 20 MB，按文件头只放行 JPEG、PNG、WebP、GIF、BMP、AVIF，原始字节返回网页（`no-store`），服务器不解码、不保存。
- 处理：浏览器 `createImageBitmap` 解码后按既有规格缩放为 thumb／grid／poster（WebP 或 JPEG，大小上限不变），原图不入库。
- 写入：`/thumbnail/claim` 带 `custom: true` 取得自定义票据。`ThumbnailService._custom_claim` 不检查媒体类型（目录与系统区除外），取消该 Blob 排队或进行中的自动任务并收回旧票据，不登记新任务；随后沿用 `POST /thumbnail`（ETag + 票据）与带 variants 的 `/thumbnail/release` 清除未更新的旧规格。之后自动流程因已有缩略图而跳过，不会覆盖用户的图片。
- 非媒体文件从不进入自动队列与补图（`_eligible` 仍只认图片、视频、音频），列表接口照常附带它们的缩略图状态，网页按通用规则显示。

## 播放器当前画面

自己的视频播放器控制条提供「将当前画面设为缩略图」，全屏与窄屏同样可用。点击时同步把当前已解码帧固定到 Canvas，再异步编码并保存三种规格，不暂停、不跳转或重新读取视频。用户明确选择的帧不套用自动画面过滤；未加载或正在跳转时禁用，保存中显示进度并防止重复提交，成功或失败在播放器内提示。

写入复用自定义票据（/thumbnail/claim 的 custom）、POST /thumbnail 和 /thumbnail/release，带 ETag、生成票据及会话／私密授权；release 可带本次成功的 variants，复核原文件和票据后移除未更新的旧规格，避免封面仍显示上一次的画面。保存后读取新缩略图版本并更新文件列表与播放列表；只读分享页不提供该按钮。

## 生成权与接管

视频质量检查使用 32×32 灰度样本：除黑白占比与整体方差外，还检查相近亮度的集中程度和 4×4 区域中的细节分布，跳过带小标志的彩色单色片头、平滑渐变，以及只有黑边的空白画面。保留有细节的暗场和正常带黑边的画面；不按某种颜色直接拒绝。后台自动生成与本地／显式浏览器生成依次尝试 0、1、3、10、30、60、120 秒，取第一个合格画面，短视频到结尾即停止；整次任务仍共用原有 45 秒与读取预算。预览补图只等待播放中合格的当前帧，不主动跳转。

自动规则作用于新生成的缩略图。已有片头缩略图不会在浏览目录时自动重新读取视频；用户可以通过文件菜单「更新缩略图」或播放器当前画面替换；成功后缩略图版本与地址更新。

网页上传提交时，后台为上传端保留 90 秒。浏览器处理本地文件或预览画面前，通过 `POST /api/user/v1/thumbnail/claim` 取得同一 Blob 的短期生成权，其他浏览器和后台不能同时处理该 Blob。浏览器本地处理最多等待 60 秒，预留时间用于提交缩略图。

提交结果带文件 ETag 与生成票据；保存各规格前复核源 Blob、内容版本和票据期限。完成或失败经 `/thumbnail/release` 主动交还；关闭页面未交还时，到期由后台接管。已经保存的缩略图会被复用，过期结果不能附到新文件上。

后台单并发，内存队列最多 128 项。普通单图生成接口处理与保存共用 45 秒期限；明确的手动请求优先，自动任务先处理图片和音频，再处理视频。任务只来自三处：写入提交、实际读取（`observe`）和手动请求；不扫描整库补图，没有任何已接收数据的自动任务直接出队，等文件被实际读取时再登记。网页预览图片或视频时，读取登记为 `waiting_client` 并给浏览器 30 秒，超时后才由后台使用同一批缓存。自动任务遇到缓存不足进入 `waiting_data`，只在收到新字节后重试，间隔从 4 秒起逐次翻倍到 60 秒，累计 6 次仍不足就放弃并记录，避免边播放边反复启动解码器；不定时下载原文件重试。重启后缓存清空，等待实际读取或手动生成。

## 保证最终生成：自动补图

即时路径（浏览器、缓存）都失败时还会缺图：缓存过期或被挤掉、服务器重启、复制／秒传／保存分享得到的文件从未被读取、数据不足放弃等。兜底的自动补图在队列空闲、没有更便宜的任务时运行：

- 浏览器读取地址：`/thumbnail?etag=<内容ETag>&variant=&v=<ETag.规格.版本>&bucket_id=`，不含路径，移动或改名后缓存仍有效；服务端用 `objects_by_etag`（schema v24）索引找到同桶内调用者按路径规则可读的文件（`ObjectService.get_thumbnail_by_etag`），旧的 `?path=` 地址继续支持。`grid`／`poster` 对象经 `BlobEngine.read_small`（4 路并发、60 秒排队）读取，不占用每桶 2 个的传输名额，避免网格视图批量请求时返回 503。
- 按 `(bucket_id, key)` 键集分页找出写入或修改超过 10 分钟、`thumbnails` 表里没有任何记录（含 `none`）的图片、视频、音频，包括私密空间，跳过系统区与已禁用账号；一次最多排 4 个，优先级低于手动和缓存任务；游标只越过已经看过的文件，名额满时这一页剩下的下次接着处理。一轮扫完后 10 分钟再从头扫（只查元数据）。
- 解码器按实际常驻内存（Linux `/proc/<pid>/status` 的 VmRSS）巡检，上限 192–512 MiB，不使用 `RLIMIT_AS`：FFmpeg 7 为每路输入、输出和滤镜各开线程，虚拟地址空间远大于实际用量，限制地址空间会让它在加载库或创建线程时直接失败（1.8.0 及以前在 x86_64 Docker 中所有后台生成都因此失败）。被信号终止、线程或内存不足、超过 RSS 上限、缺少动态库视为运行环境问题（`ThumbnailRetry`），只推迟重试，不计入「连续 3 次」，也不记 `none`。
- 升级后首次启动（settings 表 `thumbnails.repair` 未记录版本 1）一次性删除全部 `none` 记录，让旧版误记的文件重新进入自动补图。
- 每个文件沿用手动生成的回源预算（图片 60、视频 64、音频 32 MiB，按完整分片计量），先用缓存。只产生存储到服务器的入站流量，不经浏览器。
- 每日读取上限由管理员在「安全与维护 → 缩略图队列」设置：关闭、1／4（默认）／16／64 GiB 或不限制；当日用量保存在数据库，重启不清零。额度不足以处理下一个文件时暂停到第二天或调高上限。
- 解码器确定无法处理、或文件超过单文件预算时记为 `none`（界面显示类型图标），以后不再自动尝试；资源不足、缓存被回收、超时属于暂时失败，6 小时后再试，超时等计次失败连续 3 次仍失败也记为 `none`，`ThumbnailRetry` 不计次数。助手生成卡片可重新提交后台生成；文件菜单「更新缩略图」用于上传自定义图片，播放器也可保存当前画面。
- 不参与生成的类型（超过 60 MiB 的图片、SVG、PDF、Office）和没有 FFmpeg 的服务器无法保证。

## 浏览器缓存

缩略图地址由路径、规格、内容 ETag、缩略图版本与存储桶组成，匹配当前版本时返回 `Cache-Control: private, max-age=31536000, immutable`，浏览器一年内不再请求；删除、覆盖或重新生成会改变版本，地址随之变化。私密空间的缩略图地址不带解锁令牌，服务端用同一登录会话当前的私密授权校验，所以多次锁定、解锁之间缓存保持有效；授权无效时返回 423 且 `no-store`。私密原文件、列表等其他接口仍禁止持久缓存。

## 页面如何得知新缩略图

页面上的列表是读取时的快照。文件页在当前列表里有缺缩略图的图片、视频、音频时，用 `POST /api/user/v1/thumbnail/status`（私密空间走 `/private/thumbnail/status`）只查询这些文件（最多 200 个、按修改时间从新到旧）的 ETag 与缩略图状态，不重读整个目录：首次 10 秒，之后间隔逐次加倍到 5 分钟，页面隐藏时跳过，最长等 1 小时。查到缩略图就原地更新这几行；发现文件已删除或 ETag 变了（被别处覆盖）就整页后台刷新。

预览弹窗的成员与顺序在打开时固定，但文件页每次更新列表都会经 `PreviewHost.sync` 把最新的文件信息交给预览，`usePreviewPlaylist` 用它替换同名项，所以底部列表、头部图标和封面会随页面一起出现新缩略图。

## 缓存与读取预算

`BlobEngine` 保留已经传输的密文分片或密文范围，写入匿名临时文件，不保存明文或额外密钥。缓存总计最多 128 MiB，每个 Blob 最多 65 MiB，闲置 15 分钟过期；关闭进程即清除。保留有界的早期与近期分片，以兼顾音频标签、画面和尾部索引。多文件上传超过预算时允许回收缓存，不能以重新下载填补自动任务的缓存缺失。

普通单图生成接口沿用图片 60 MiB、视频 64 MiB、音频 32 MiB 的逻辑预算，按不同的源字节范围累计：同一次任务的多个 FFmpeg 选帧进程会重复探测文件头、尾部索引和关键帧，这些重复或重叠范围合并后只计算一次。该限制不是视频总大小上限，也不是重复交付给解码器的累计流量。真正新增的读取范围超过上限仍会停止。

回源预算独立按实际取回的完整密文分片计量，预留 1 MiB 加密帧开销；命中缓存不扣回源额度，缓存被回收后停止，避免反复下载同一分片。回源超额明确提示“缩略图回源读取量超过预算”，与逻辑范围预算区分。`_RangeInput(..., budget=None)` 仍保留不限读取量的模式（目前没有入口使用），缓存不足或回收后可以按需重新取回所需分片，仍分窗口交付并逐块复核授权，不将完整视频放入内存。缓存自身继续保持有界，整次处理与保存仍共用 45 秒。图片最多 4000 万像素，视频最多 4096×2160 像素。

FFmpeg 只能通过绑定当前 Blob 的短期回环入口读取，禁止外部引用和播放列表。输入不合并成完整明文文件，少量输出 JPEG 在临时目录中生成并清理。列表小图加密存数据库；网格图和封面作为加密系统区对象保存，仍有少量生成结果的写入流量。

## 私密空间、删除与覆盖

私密空间锁是网页访问授权，文件仍由系统 KEK 保护。内部后台任务不持有网页解锁票据，不受私密空间锁定或页面关闭限制；系统整体锁定、账号禁用或源版本失效仍会中止。网页访问私密文件、缩略图及手动操作继续要求私密解锁，管理员队列不提供读取入口。

删除、覆盖、移入回收站会取消失效任务、浏览器生成权与正在运行的处理，释放缓存。改名或仍有副本引用同一 Blob 时，可将任务转到有效位置，沿用缓存；旧路径的生成票据作废。每次读取及保存也检查源文件，防止事件通知与处理并发时保存过期结果。重新生成失败时保留原缩略图。

## 管理员可见性

「安全与维护 → 缩略图队列」展示待处理、等待浏览器、等待数据、处理中和最近结果，以及缓存量和本进程手动回源读取量。接口 `GET /api/admin/v1/maintenance/thumbnails` 校验管理员角色，普通用户返回 403；只返回匿名任务编号、类型、状态与固定说明，不返回文件名、路径、账号身份或私密内容。普通用户不查询后台队列。

最近结果区分读取预算不足、候选画面均为空白或细节不足、没有内嵌封面、媒体解析或编码不受支持、画面转换失败和运行环境受限；写入 `none` 不能显示为缩略图已完成。未识别的异常只显示固定排查提示。服务日志使用相同匿名任务编号，记录固定的 `reason`、异常类型或 FFmpeg 退出码，不记录原始 stderr、异常正文、文件路径、来源地址或凭据。
