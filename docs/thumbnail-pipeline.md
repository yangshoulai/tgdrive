# 缩略图处理流程

支持图片、视频、音频内嵌封面，不处理 PDF、Office、SVG 或系统区助手附件。首要约束是减少原文件的重复传输。

| 场景 | 处理方式 | 额外读取原文件 |
| --- | --- | --- |
| 网页上传 | 浏览器使用本地 File，后台等待上传端 | 无 |
| 浏览目录、搜索、网格、滚动 | 只加载已有缩略图，缺图显示类型图标 | 无 |
| 图片预览 | 直接缩放已经加载的原图 | 无 |
| 视频预览 | 只截取通过画面质量检查的当前已解码画面，不因播放时长放行，不跳转、不另建播放器 | 无 |
| 音频预览 | 原生播放器不向网页开放缓冲字节，后台复用实际交付的数据提取封面 | 无 |
| 服务端自动队列 | 复用上传、下载任务、真实预览已收到的密文缓存，不足就等待；完全没有数据的任务不入队 | 无 |
| 复制、秒传、保存他人分享 | 同一 Blob 已有缩略图直接复用；没有时等文件被实际读取 | 无 |
| 文件菜单中视频「生成／重新生成缩略图」 | 后台准备候选画面，用户在弹窗中选择后才保存 | 用户明确触发时按需读取 |
| 文件菜单中图片／音频手动生成 | 服务端先用缓存，必要时按预算读取存储分片 | 用户明确触发时允许 |

文件助手的生成卡片仍需用户点击，点击后逐个提交与文件菜单相同的手动请求（队列满时等待再提交），由服务器优先用缓存、按预算回源，不在浏览器下载原文件——服务器取存储是入站流量，浏览器下载则多一份出站流量。只有服务器没有 FFmpeg 时，卡片才退回浏览器读取文件生成。

## 职责划分

| 角色 | 负责 | 不做 |
| --- | --- | --- |
| 上传页 | 用本地 File 生成三种规格并保存 | 不等待后台、不重复读取已上传数据 |
| 预览页 | 图片用已加载原图、视频用已解码画面 | 不为截图另开请求、不跳转播放进度 |
| 后台队列 | 音频封面、S3／访问密钥／离线下载写入的文件、浏览器超时或失败的接管、手动生成 | 即时自动任务不回源 |
| 自动补图 | 写入 10 分钟后仍缺图的文件，按单文件预算与每日额度从存储读取 | 不产生出站流量；不重试已确定无法生成的文件 |
| 管理员 | 在「安全与维护」查看匿名队列 | 看不到文件名、路径、账号 |

## 手动视频选图

上传、本地文件生成、预览补图、后台自动补图和助手批量生成沿用原流程。只有文件菜单里视频的手动入口打开「选择视频缩略图」弹窗，普通与私密空间共用组件；图片和音频的手动入口不变。

- 候选数量在「安全与维护 → 缩略图队列 → 手动生成视频候选截图」设置，范围 1–9 张，默认 3 张，存于现有 settings 键 `thumbnails.candidates`；无需数据库迁移。管理员接口仍校验角色与 CSRF，`POST /api/admin/v1/maintenance/thumbnails` 接受 `{candidate_count}`，GET 状态附带当前数量。
- 开头只用于复用 FFmpeg 已读取的时长信息，不作为候选。已知时长时，先在全片 10%–90% 之间均匀选点：默认 3 张为 10%／50%／90%，9 张为 10%／20%／…／90%，1 张取中点；主采样点全部尝试后才补取附近位置，不重新按时间排序。无时长信息时按 5／15／30／60／120 秒等逐步拉开间隔，解码到结尾停止。
- 手动候选使用独立的 64×64 灰度分析，结合多种宽度的亮度集中程度与分区细节，跳过黑白屏、灰底文字（包括缩小后的抗锯齿）等明显片头；已接受帧之间过于相似的跳过。不会为凑满数量放行不合格帧。检查属于画面启发式，最终由用户选择，不声称能识别所有文字片头。
- 手动候选按需读取，不设固定累计读取量或总处理时限；共用受控 `_RangeInput` 和已有密文缓存，分窗口流式交付，缓存回收后允许重新读取。持续寻找配置数量的合适画面，只有采样位置已遍历、用户取消或实际读取／解码失败时结束，不用自动生成预算提前中止。候选期间不写入正式缩略图、不记 `none`，取消或失败保留旧图；实际失败前已有画面时保留可选项并说明真实原因。
- 候选的三种规格使用源 Blob 的缩略图子密钥加密，附加数据绑定本次请求、序号与规格，只在进程内短存，生成完成后保留 10 分钟，最多 16 份请求；排队、截帧及保存期间不因该保留期限而中断。每份至多 9 张、每种规格沿用既有图片大小限制，不另设共享候选字节额度。关闭弹窗取消任务并释放候选与生成权，进程停止清空；临时解码文件沿用原流程立即清理。
- 创建、状态、读取、选择与取消都绑定当前登录会话及原文件的存储桶、路径、ETag 和 Blob。网页读取及保存私密候选仍需当前私密解锁，候选图返回 `no-store`，前端通过带会话头的请求读取并使用临时 Blob URL，关闭或锁定后撤销 URL。后台内部截帧沿用原系统密钥和账号校验。
- 确认后只保存所选帧的规格，再统一更新版本，保存不套用自动任务的总处理时限；保存期间复核会话、私密授权与源版本，后台和浏览器生成权让出该 Blob。空间不足时沿用既有规则：完全无法保存则保留旧图；已保存小图时移除未更新的旧规格，让大图退回选中的小图。

网页接口（私密路径在 `/api/user/v1/private` 下，普通在 `/api/user/v1` 下）：

| 接口 | 参数与用途 |
| --- | --- |
| `POST /thumbnail/candidates` | `{path, etag}` 创建请求，返回 id、状态、目标数量、候选序号及时间 |
| `POST /thumbnail/candidates/status` | `{path, etag, id}` 查询进度与候选元信息，不返回图片字节 |
| `GET /thumbnail/candidate` | `path, etag, id, index`，返回受保护的 JPEG，不缓存 |
| `POST /thumbnail/candidates/select` | `{path, etag, id, index}` 保存所选帧，提交前复核原文件 |
| `POST /thumbnail/candidates/cancel` | `{path, etag, id}` 取消任务并释放临时候选 |

## 播放器当前画面

自己的视频播放器控制条提供「将当前画面设为缩略图」，全屏与窄屏同样可用。点击时同步把当前已解码帧固定到 Canvas，再异步编码并保存三种规格，不暂停、不跳转或重新读取视频。用户明确选择的帧不套用自动画面过滤；未加载或正在跳转时禁用，保存中显示进度并防止重复提交，成功或失败在播放器内提示。

写入复用 /thumbnail/claim、POST /thumbnail 和 /thumbnail/release，带 ETag、生成票据及会话／私密授权；release 可带本次成功的 variants，复核原文件和票据后移除未更新的旧规格，避免封面仍显示上一次的画面。保存后读取新缩略图版本并更新文件列表与播放列表；只读分享页不提供该按钮。

## 生成权与接管

视频质量检查使用 32×32 灰度样本：除黑白占比与整体方差外，还检查相近亮度的集中程度和 4×4 区域中的细节分布，跳过带小标志的彩色单色片头、平滑渐变，以及只有黑边的空白画面。保留有细节的暗场和正常带黑边的画面；不按某种颜色直接拒绝。后台自动生成与本地／显式浏览器生成依次尝试 0、1、3、10、30、60、120 秒，取第一个合格画面，短视频到结尾即停止；整次任务仍共用原有 45 秒与读取预算。预览补图只等待播放中合格的当前帧，不主动跳转。

自动规则作用于新生成的缩略图。已有片头缩略图不会在浏览目录时自动重新读取视频；文件菜单「重新生成缩略图」现在进入上面的候选选择流程。确认成功后缩略图版本与地址更新，找不到合格画面则保留旧图并报告失败。

网页上传提交时，后台为上传端保留 90 秒。浏览器处理本地文件或预览画面前，通过 `POST /api/user/v1/thumbnail/claim` 取得同一 Blob 的短期生成权，其他浏览器和后台不能同时处理该 Blob。浏览器本地处理最多等待 60 秒，预留时间用于提交缩略图。

提交结果带文件 ETag 与生成票据；保存各规格前复核源 Blob、内容版本和票据期限。完成或失败经 `/thumbnail/release` 主动交还；关闭页面未交还时，到期由后台接管。已经保存的缩略图会被复用，过期结果不能附到新文件上。

后台单并发，内存队列最多 128 项。普通单图生成接口处理与保存共用 45 秒期限；视频文件菜单的候选生成及所选画面保存不套用此期限。明确的手动请求优先，自动任务先处理图片和音频，再处理视频。任务只来自三处：写入提交、实际读取（`observe`）和手动请求；不扫描整库补图，没有任何已接收数据的自动任务直接出队，等文件被实际读取时再登记。网页预览图片或视频时，读取登记为 `waiting_client` 并给浏览器 30 秒，超时后才由后台使用同一批缓存。自动任务遇到缓存不足进入 `waiting_data`，只在收到新字节后重试，间隔从 4 秒起逐次翻倍到 60 秒，累计 6 次仍不足就放弃并记录，避免边播放边反复启动解码器；不定时下载原文件重试。重启后缓存清空，等待实际读取或手动生成。

## 保证最终生成：自动补图

即时路径（浏览器、缓存）都失败时还会缺图：缓存过期或被挤掉、服务器重启、复制／秒传／保存分享得到的文件从未被读取、数据不足放弃等。兜底的自动补图在队列空闲、没有更便宜的任务时运行：

- 浏览器读取地址：`/thumbnail?etag=<内容ETag>&variant=&v=<ETag.规格.版本>&bucket_id=`，不含路径，移动或改名后缓存仍有效；服务端用 `objects_by_etag`（schema v24）索引找到同桶内调用者按路径规则可读的文件（`ObjectService.get_thumbnail_by_etag`），旧的 `?path=` 地址继续支持。`grid`／`poster` 对象经 `BlobEngine.read_small`（4 路并发、60 秒排队）读取，不占用每桶 2 个的传输名额，避免网格视图批量请求时返回 503。
- 按 `(bucket_id, key)` 键集分页找出写入或修改超过 10 分钟、`thumbnails` 表里没有任何记录（含 `none`）的图片、视频、音频，包括私密空间，跳过系统区与已禁用账号；一次最多排 4 个，优先级低于手动和缓存任务；游标只越过已经看过的文件，名额满时这一页剩下的下次接着处理。一轮扫完后 10 分钟再从头扫（只查元数据）。
- 解码器按实际常驻内存（Linux `/proc/<pid>/status` 的 VmRSS）巡检，上限 192–512 MiB，不使用 `RLIMIT_AS`：FFmpeg 7 为每路输入、输出和滤镜各开线程，虚拟地址空间远大于实际用量，限制地址空间会让它在加载库或创建线程时直接失败（1.8.0 及以前在 x86_64 Docker 中所有后台生成都因此失败）。被信号终止、线程或内存不足、缺少动态库视为运行环境问题（`ThumbnailRetry`），只推迟重试，不计入「连续 3 次」，也不记 `none`。
- 升级后首次启动（settings 表 `thumbnails.repair` 未记录版本 1）一次性删除全部 `none` 记录，让旧版误记的文件重新进入自动补图。
- 每个文件沿用手动生成的回源预算（图片 60、视频 64、音频 32 MiB，按完整分片计量），先用缓存。只产生存储到服务器的入站流量，不经浏览器。
- 每日读取上限由管理员在「安全与维护 → 缩略图队列」设置：关闭、1／4（默认）／16／64 GiB 或不限制；当日用量保存在数据库，重启不清零。额度不足以处理下一个文件时暂停到第二天或调高上限。
- 解码器确定无法处理、或文件超过单文件预算时记为 `none`（界面显示类型图标），以后不再自动尝试；资源不足、缓存被回收、超时属于暂时失败，6 小时后再试，连续 3 次仍失败也记为 `none`。文件菜单的手动生成始终可以重试。
- 不参与生成的类型（超过 60 MiB 的图片、SVG、PDF、Office）和没有 FFmpeg 的服务器无法保证。

## 浏览器缓存

缩略图地址由路径、规格、内容 ETag、缩略图版本与存储桶组成，匹配当前版本时返回 `Cache-Control: private, max-age=31536000, immutable`，浏览器一年内不再请求；删除、覆盖或重新生成会改变版本，地址随之变化。私密空间的缩略图地址不带解锁令牌，服务端用同一登录会话当前的私密授权校验，所以多次锁定、解锁之间缓存保持有效；授权无效时返回 423 且 `no-store`。私密原文件、列表等其他接口仍禁止持久缓存。

## 页面如何得知新缩略图

页面上的列表是读取时的快照。文件页在当前列表里有缺缩略图的图片、视频、音频时，用 `POST /api/user/v1/thumbnail/status`（私密空间走 `/private/thumbnail/status`）只查询这些文件（最多 200 个、按修改时间从新到旧）的 ETag 与缩略图状态，不重读整个目录：首次 10 秒，之后间隔逐次加倍到 5 分钟，页面隐藏时跳过，最长等 1 小时。查到缩略图就原地更新这几行；发现文件已删除或 ETag 变了（被别处覆盖）就整页后台刷新。

预览弹窗的成员与顺序在打开时固定，但文件页每次更新列表都会经 `PreviewHost.sync` 把最新的文件信息交给预览，`usePreviewPlaylist` 用它替换同名项，所以底部列表、头部图标和封面会随页面一起出现新缩略图。

## 缓存与读取预算

`BlobEngine` 保留已经传输的密文分片或密文范围，写入匿名临时文件，不保存明文或额外密钥。缓存总计最多 128 MiB，每个 Blob 最多 65 MiB，闲置 15 分钟过期；关闭进程即清除。保留有界的早期与近期分片，以兼顾音频标签、画面和尾部索引。多文件上传超过预算时允许回收缓存，不能以重新下载填补自动任务的缓存缺失。

普通单图生成接口沿用图片 60 MiB、视频 64 MiB、音频 32 MiB 的逻辑预算；按完整密文分片计回源预算，预留 1 MiB 加密帧开销，缓存回收后停止以避免自动反复读取。视频文件菜单的手动候选使用 `_RangeInput(..., budget=None)`，不设固定读取量，缓存不足或回收后可以按需重新取回所需分片，仍分窗口交付并逐块复核授权，不将完整视频放入内存。缓存自身继续保持有界。图片最多 4000 万像素，视频最多 4096×2160 像素。

FFmpeg 只能通过绑定当前 Blob 的短期回环入口读取，禁止外部引用和播放列表。输入不合并成完整明文文件，少量输出 JPEG 在临时目录中生成并清理。列表小图加密存数据库；网格图和封面作为加密系统区对象保存，仍有少量生成结果的写入流量。

## 私密空间、删除与覆盖

私密空间锁是网页访问授权，文件仍由系统 KEK 保护。内部后台任务不持有网页解锁票据，不受私密空间锁定或页面关闭限制；系统整体锁定、账号禁用或源版本失效仍会中止。网页访问私密文件、缩略图及手动操作继续要求私密解锁，管理员队列不提供读取入口。

删除、覆盖、移入回收站会取消失效任务、浏览器生成权与正在运行的处理，释放缓存。改名或仍有副本引用同一 Blob 时，可将任务转到有效位置，沿用缓存；旧路径的生成票据作废。每次读取及保存也检查源文件，防止事件通知与处理并发时保存过期结果。重新生成失败时保留原缩略图。

## 管理员可见性

「安全与维护 → 缩略图队列」展示待处理、等待浏览器、等待数据、处理中和最近结果，以及缓存量和本进程手动回源读取量。接口 `GET /api/admin/v1/maintenance/thumbnails` 校验管理员角色，普通用户返回 403；只返回匿名任务编号、类型、状态与固定说明，不返回文件名、路径、账号身份或私密内容。普通用户不查询后台队列。
