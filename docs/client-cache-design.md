# 浏览器本地缓存设计

目标：自动保留所有可预览文件已读取的内容（图片、音视频、Markdown、文本、代码、PDF）及缩略图，并允许用户手动缓存任意类型的完整文件；完整、部分与零字节缓存都能逐项或批量清除。降低重复读取与 Telegram 流量，私密文件在锁定后即使拿到整个浏览器目录也无法解开。

## 1. 总体结构

```
页面 媒体／文本 fetch／PDF iframe ──► Service Worker（/sw.js，作用域 /）
                                   │ 命中：从 IndexedDB 读密文块 → WebCrypto 解密 → 206/200
                                   │ 缺失：fetch(cache:'no-store') 回源 → 边转发边加密写块
                                   ▼
                              服务端 /api/user/v1/cache/*（密钥、对账及限定范围的后台缓存读取）
```

- Service Worker 只处理带内容版本的 GET：`/api/user/v1/content`（`v`=ETag 且带 `bucket_id`）、`/api/user/v1/thumbnail`（`etag`+`v`）、以及对应的 `/api/user/v1/private/...`。预览入口按 `canPreview` 统一附加 `preview=1`，媒体及带此标记的文本、代码、PDF 自动建立条目，不在 Worker 重复维护扩展名规则；其他类型仍可手动完整缓存。`download=1` 仅在本机已有完整条目时命中，否则直接回源且不写入缓存。其余请求不调用 `respondWith`。
- 本人文件的预览、下载与手动缓存地址另带同一 ETag 对应的原始大小 `size`。读取时若本机条目大小不符，删除条目并正常回源，同时清除内存索引，修复旧版误记为 0 字节的缓存。
- 自动读取出现异常时退回直接请求服务器；手动缓存必须报告写入错误，不能把仅完成网络接收当成缓存成功。浏览器不支持或用户关闭时正常文件访问仍可使用。
- 回源请求一律 `cache: 'no-store'`，浏览器 HTTP 缓存不再保存明文。私密响应（含私密缩略图）服务端改为 `no-store`。
- 存储使用 IndexedDB（所有平台的 Service Worker 都稳定可用）。数据按 1 MiB 分块稀疏保存，视频看过哪段存哪段；拖动时缓存块与回源片段拼成同一个连续响应。
- 文本、Markdown 和代码最多展示 16 MiB，额外读取 1 字节用于判断截断。文本与 PDF 的预览范围停在块中间时，在交付最后一段前补齐当前 1 MiB 缓存块（最多额外读取不到 1 MiB），防止页面取消读取后整块丢失；不主动补齐整个大文件。空文本的 Range 416 经 HEAD 验证内容版本后可登记为空文件，缓存命中时仍返回 `Content-Range: bytes */0`，供文本预览识别为空内容。
- 没有本机条目时，未带 `preview=1` 的 `document`／`iframe`／`embed` 等请求，以及关闭「自动缓存视频片段」时的 `<video>` 请求，直接按原请求回源，不先发块对齐请求再丢弃（否则 Safari 每次拖动都会回源两次）；脚本、样式等请求始终不自动建立条目。
- 非缩略图数据块提交后清除内存索引，并广播不含文件名与路径的状态变化，普通进度最多每两秒通知一次，完成或逐项清除立即通知。页面查询期间收到通知会在当前查询结束后补刷，关闭预览也刷新索引，空闲时仍每 20 秒兜底刷新。
- 上游请求绑定 `AbortController`：`<video>` 放弃请求时同步中止回源，不额外预读（与服务端渐进窗口的设计一致）。
- 缓存块缺失、损坏或本地存储读取失败时，删除坏条目，并从尚未交付的位置继续回源；已经返回给播放器的响应流不要求用户重新打开。首次 Range 回源按块对齐后，若版本变化或不能缓存，丢弃该响应并按原始 Range 重新请求。
- 带自定义 Range 的回源一律按原地址另建同源请求（`sourceFetch`），不能用 `fetch(request, { headers })`：音视频元素的请求是 no-cors 模式，浏览器会丢掉脚本改写的 Range 并返回整个文件。只有 ETag 与条目版本不同才视为文件已变化并删除条目；版本相同但没有按 Range 返回（200）只放弃本次读取，已缓存的块保留。修复前回源丢失 Range 会被误判为文件变化，播放中的自动缓存被反复清空，手动缓存因此从零开始。

## 2. 密钥

| 名称 | 位置 | 说明 |
|---|---|---|
| KEK | 服务端内存 | 系统主密钥，由加密口令派生，锁定即丢弃 |
| C（缓存主密钥） | `settings.client_cache.key` | 随机 32 字节，用 `derive_subkey(KEK, "client-cache")` 包裹；改口令时 `keystore.rotate` 只重新包裹 |
| K_tier | 服务端计算、浏览器内存 | `HMAC(C, tier‖层‖用户‖设备‖纪元‖sha256(密码哈希))`；普通层会话有效即下发，私密预览需解锁，缓存任务创建时取得所需密钥；任务上下文仅供补全缓存 |
| 条目基密钥 | 浏览器内存 | 普通层：`HKDF(K_tier, "entry|"+etag)`；私密层：服务端 `HMAC(C, entry‖…‖etag)` 逐个下发 |
| 条目编号／块密钥 | 浏览器内存 | 由条目基密钥按缓存版本（内容 ETag，或缩略图 `etag|规格|版本`）派生：编号 `HMAC`，块密钥 `HKDF` → AES-256-GCM |

- 密钥只存在 Service Worker 内存里，不落盘；Service Worker 被浏览器停止后重新获取（一次小请求）。
- 普通层的条目派生缓存属于当前层级密钥上下文，重新获取上下文后重新派生，不能跨纪元或密码版本复用。私密条目首次向服务端获取版本密钥，同一有效私密授权期间在 Worker 内复用基密钥和派生结果，音视频拖动进度无需逐个 Range 重新取密钥；并发首次请求仍合并成批（每批不超过 500 项），失败结果不缓存。没有同步授权截止时间的旧页面仍逐次验权。
- 页面沿用 `PrivateSessionProvider` 的状态检查，将服务端已确认的私密授权截止时间同步给 Worker，播放活动照常续期；Worker 自己也按该截止时间撤销私密读取上下文。锁定、退出、授权更换、到期或重置清除旧密钥，迟到请求不能恢复。无需新增授权或单独的播放票据。
- 设备编号是浏览器生成的随机串，存在 IndexedDB；同一账号不同设备密钥不同。
- 纪元在 `users.cache_epoch`（schema v26）。用户「重置所有设备的缓存」只需加一；改密码因密码哈希参与派生而自动失效。
- 命名空间 `HMAC(C, ns‖用户)` 区分同一浏览器里的不同账号，本地不出现账号 ID。

## 3. 本地数据

- `entries`：键 `命名空间/层/编号`；明文字段只有层、块序号列表、已存字节数、最后访问时间、普通层的大类（图片／视频／音频／缩略图／其他，供统计）；路径、类型、ETag、文件大小与手动缓存标记 `manual` 放在加密的 `info` 里。增加可选标记兼容现有 IndexedDB 结构，无需升级数据库。
- `blocks`：键 `条目键/块序号`，值为 `nonce(12) ‖ AES-GCM 密文 ‖ 标签`，AAD 为 `命名空间|层|编号|块序号`，块被调换或拼接会解密失败；解密失败即删除该条目并回源。
- 暴露的元数据：总占用、条目数、每个条目的大致大小与访问时间。私密层不记录大类。

## 4. 失效与删除

- 正确性：只有页面用最新列表里的 ETag 发起请求才会命中，已删除或被覆盖的文件不会被展示。
- 普通层对账：Service Worker 启动后、页面执行写操作后（防抖）以及每 15 分钟，把本地条目的 ETag 分批（≤500）交给 `POST /api/user/v1/cache/check`，只保留普通区（不含回收站、私密空间、系统区）仍引用的版本。
- 私密层：首次读取版本时通过 `POST /api/user/v1/private/cache/keys` 获取密钥；页面发出文件变更通知后清除复用结果，下次读取重新验权。对账继续检查私密区（不含私密回收站）的版本引用，返回 null 时删除条目和对应密钥，密钥纪元变化或授权被拒绝时撤销私密上下文。其他设备造成的状态变化由已有的私密状态检查及缓存对账发现，不在每次拖动进度时发送密钥请求；离线不能延长授权截止时间。
- 401 只丢弃内存中的密钥，不删除数据（重新登录同一账号可继续使用）；解不开索引的条目（纪元或密码已变）在对账时删除。
- 私密条目不按天数过期（原管理员「私密文件保留天数」已移除），按容量与最后访问时间淘汰，用户关闭本机私密缓存时整层清除；锁定、闲置到期时页面通知 Service Worker 丢弃预览和普通缓存读取的私密上下文，已加入的后台缓存任务继续（见 §6.2）；退出时丢弃所有上下文并停止缓存任务。
- 锁定、退出或重置通知同时撤销对应的旧上下文，取消尚未交付的预览读取；通知前发出的预览密钥请求即使稍后成功，也不能恢复旧上下文或重新交付私密内容。

## 5. 策略

- 没有管理员策略：缓存在用户自己的设备上（Chrome／Edge 还可以放在用户选择的本地文件夹里），既减轻服务器负担，也只由设备使用者决定。旧版的 `/api/admin/v1/client-cache`、settings 表 `client_cache.policy`（`enabled`、`private_enabled`、`private_ttl_days`）已移除，旧值不再读取；`/cache/session` 返回的 `policy` 固定为全部允许，只为兼容旧页面。私密层仍需要当前登录会话已解锁私密空间才能取得密钥。
- 设备（设置 →「本机缓存」，存在 IndexedDB）：开关、普通层与私密层容量（浏览器配额是硬上限，设置页显示可用空间）、是否缓存视频（Safari／iOS 默认关闭）、是否在本机缓存私密文件、私密上限；查看占用与条目、按层清理、重置所有设备的缓存密钥（审计 `client_cache.reset`）。
- 自动缓存的单个文件最多占所在层容量的一半（一个长视频不会挤掉其他缓存），手动缓存可以用满整层容量。超出上限时先按最后访问时间淘汰自动缓存，只有自动缓存全部移除后仍超出（例如用户调低了上限）才淘汰手动缓存；开启时申请 `navigator.storage.persist()`。默认上限普通层 10 GB、私密层 2 GB（未保存过设置的设备随之生效），可选 256 MB–500 GB。设置页只列出不超过 `navigator.storage.estimate().quota` 的选项；Worker 读取设置时同样用 `effectiveMiB` 把两层容量截断到配额，已保存的超额值在设置页标注「超出浏览器可用空间」并按配额生效。
- 本地缓存目录（桌面 Chrome／Edge，按 `showDirectoryPicker` 特性检测）：设置页「缓存位置」可选择一个本地文件夹，句柄存 IndexedDB meta 的 `directory`。新条目（`EntryRecord.store = "dir"`）的加密块写到 `<文件夹>/tessera-cache/<命名空间>/<层>/<条目编号>/<块序号>`，每块用 `createWritable` 写完整后再登记到条目；条目元数据、密钥与索引仍在 IndexedDB，离开 Tessera 无法解开文件。目录已授权时容量不按浏览器配额截断，也不做浏览器配额预留；磁盘写满按 `QuotaExceededError` 报错。Service Worker 只能查询授权：重启浏览器后若变为 prompt，自动缓存直接回源、不改写到浏览器存储，手动缓存报「需要重新授权」，目录条目保留不删；页面在设置页、本机缓存页与每次登录一次的提示中提供「重新授权」（Chrome 122 起可选「每次访问时都允许」）。已在浏览器存储中的旧条目继续可用，手动补全未完成的旧条目时改到目录重新缓存。更换文件夹或「改回浏览器存储」删除目录条目及 `tessera-cache` 子文件夹；`sweepDirectory` 在目录重新可用时清理没有条目的残留文件夹。不支持的浏览器在设置页说明受浏览器限制，并建议在电脑上用 Chrome 或 Edge 打开。
- 统计（`stats` 消息）只读明文字段（字节数、条目数、大类），不解密条目，侧栏「已用空间」展开时也读取它，单列「本机缓存」（不计入配额、不参与占比条，附「管理」入口）。
- 设置不再列出已缓存的文件（文件列表的缓存图标标记与右键「清除本机缓存」已能覆盖），清理只按层：全部清理（`clear` scope `all`，含缩略图与其他账号留下的条目）、清理普通缓存、清理私密缓存。Worker 仍保留 `items` 消息供以后的界面或助手使用：分页（每页 ≤200）：Worker 解密一次普通层索引并在内存保留 15 秒，在其中按名称或路径搜索、按类型（图片／视频／音频／其他）与状态（完整／部分）筛选、按最近打开／占用／名称排序；`remove-items` 按同样条件批量移除。缩略图不列出。

## 6. 安全边界

- 服务端拒绝除 `/sw.js` 外所有带 `Service-Worker: script` 请求头的请求，用户上传的同源脚本不能被注册为常驻 Service Worker。
- `/sw.js` 地址固定，`Cache-Control: no-cache`。
- 挡不住的：解锁期间的 XSS、已经解密展示过的内容、正在播放的设备内存中的密钥（直到下一次对账或锁定）。
- iOS：ITP 可能在 7 天无交互后清除站点存储（添加到主屏幕的 Web App 例外）；Service Worker 回应 `<video>` 的 206 需要真机验证，因此 Safari 默认不缓存视频。

## 7. 回归验证

- `node --test tests/test_client_cache.cjs tests/test_client_cache_worker.cjs`：纯函数、加密、事务回滚，以及实际 Worker 的 fetch／message、有效授权期间的密钥复用与续期、旧页面逐读授权、撤销竞态、纪元更新、损坏块恢复、流取消、Range 降级和手动任务。Worker 测试用内存存储与服务端替身，响应流和加密使用原生实现；IndexedDB 与浏览器接管另做真实浏览器验证。
- `python -m unittest tests.test_client_cache_tasks`：缓存任务的纯内存回归，覆盖会话、作用域、策略和密码／纪元变化、复用任务编号、锁定后继续、流式复核及断连取消，不建立或修改数据库。
- `.venv-net/bin/python -m unittest tests.test_client_cache`：服务端密钥绑定、私密授权、对账范围、策略与脚本注册边界。

## 8. 手动缓存完整文件

- 文件列表的快捷操作仍是分享；「缓存到本机」在更多菜单与本人文件的预览头部。列表与网格为已缓存的文件和进行中的任务显示状态标记（跟在文件名后）：完整缓存共用硬盘图标，去掉「本机」「自动」文字；手动为绿色，自动为灰色描边（随访问出现、空间不够时先被淘汰），悬停说明与无障碍名称保留来源，预览头部沿用同一图标与颜色规则，部分缓存显示百分比，另有进行中进度环与失败重试；完整的自动缓存可在菜单或详情中「标记为手动缓存」。勾选多个文件后，选择栏有「缓存到本机」，右键菜单另有「清除 N 个文件的本机缓存」；单个文件的右键与 ⋯ 菜单有「清除本机缓存」。文件夹的右键与 ⋯ 菜单也提供「缓存到本机」；确认时明确说明会缓存该文件夹及全部子目录中的所有文件，混选文件与文件夹时同样确认递归范围。公开访客与附件专用接口不参与。
- 状态为未缓存、部分缓存、排队、进行中、暂停、已缓存、失败。部分缓存显示比例并可继续；进行中点击打开「任务中心 → 本机缓存」页面，已缓存点击查看说明。「缓存任务」标签支持搜索、状态筛选、每页 50 项与多选暂停／继续；暂停保留已写入的块，继续只补齐缺失内容。删除任务记录只停止并移除队列项；清除本机缓存另行确认并删除本机副本。空文件、尚未写满首块的部分缓存与完整缓存都能逐项或批量清除。关闭窗口只隐藏，记录保留到用户清理；刷新或关闭网页仍按原规则停止本机工作。
- 文件夹遍历由 `cache-folders.ts` 逐页读取（每页 200 项；普通目录使用文件列表接口，私密目录使用任务专用列表接口），忽略当前搜索、公开及类型筛选，按目标前缀限制范围，合并重复／嵌套的目录并排除目录标记；每页立即加入原有单文件队列，不先收集整个目录树的文件。相同内容版本、正在缓存及已手动完整缓存的文件不重复加入。添加过程也计入侧栏「本机缓存」的数量，可在本机缓存页停止添加；读取失败保留已加入的文件与重试入口，不误报全部完成。
- 页面外壳 `CacheTasksProvider` 维护内存队列，切换目录、我的文件或其他页面继续执行，私密任务在解锁时创建，后续复用登录会话执行，不依赖当前路由或后续私密锁定状态，仍受缓存策略限制。Worker 在所有标签页间只允许一个手动任务，以消息来源的客户端编号绑定任务；其他页面等待当前任务，不能用任务编号取消或推进别人的任务。
- `start` 消息重新取得策略，以 HEAD 校验权限、ETag 和大小；先检查设备上这一层的容量：同层其他手动缓存加上这个文件超过上限时直接报错（`CacheFatal`），请用户清理手动缓存或提高上限；否则为完整大小预留空间，由 `enforce` 按 LRU 先清理自动缓存。随后检查浏览器可用空间估计，不够时（`reserveQuota`）按 LRU 移除整台设备上的自动缓存（含其他账号与私密层），仍不够则报错。手动缓存不会被自动缓存或其他手动任务挤掉。
- 失败分两类：`CacheFatal`（空间不足、文件已变化、设置或策略不允许、4xx 等）经消息的 `fatal` 标记交给页面，直接显示失败；其余（网络中断、5xx／429、Worker 被浏览器回收导致任务丢失、消息超时等）由页面的缓存队列按 1／3／8／15／30／60 秒自动重试，重新 `start` 后只补齐缺失块，期间写入新数据会把重试计数清零，任务状态显示「自动重试」。
- 手动缓存优先采用地址中同版本的原始大小；旧地址缺少 `size` 时只接受明确有效的 `Content-Length`，响应缺失或无效时报告错误，不能把未知大小当成空文件。手动缓存重建元信息后同步清除内存索引，避免继续显示旧的大小。
- 多线程缓存：文件按 16 MiB 分段（`SEGMENT_BLOCKS`，与服务器 Telegram 分片对齐，一段只对应一个分片），`step` 消息每次并行补齐至多「并行数 × 2」个段，每段取段内第一处连续缺失；并行数为 `/upload-config` 的 `read_concurrency`（每账号读取路数）减一、最多 3，所有文件的回源请求共用这个上限（`manualSlot`），也给浏览器对同一站点的连接数留余量。Worker 同时最多 3 个手动任务（`MAX_MANUAL_FILES`，页面 `CACHE_FILE_CONCURRENCY` 一致），同一内容版本只能有一个任务。回源请求带 `X-Tessera-Background: cache`：服务器为播放和预览保留一路名额，并直接用后端大窗口读取。某段遇到不可恢复错误（文件已变化、空间不足）时中止其余段，临时故障只让该段失败，已写入的块保留。
- 每段沿用 1 MiB AES-GCM 数据块；每个块的 IndexedDB 事务提交后才通知页面进度。元信息更新不得覆盖并发预览写入的块列表；写入异常显式回滚整个事务，避免块索引提交却没有对应的数据。
- 进度以条目中已提交的逻辑字节为准，包含自动缓存或上次任务留下的块。全部块及总大小吻合后才视为完成，并再次 HEAD 复核当前版本。读不到完整响应、版本变化、配额不足、条目被清理均报告失败；取消立即中止回源，保留已提交部分。
- 列表状态来自 `index` 消息：返回当前账号全部非缩略图条目的 `层:ETag`、进度与 `manual` 标记。条目明文带 `manual` 标记（与加密 info 一致，1.11.0 的旧条目首次建索引时解密补上；私密层在私密授权可用时补）；条目的 ETag 与大小写入后不变，Worker 按条目键记住解密结果，重建索引时只解密新条目，结果在内存保留 5 秒（页面空闲时 20 秒刷新一次），页面一次取回后按 `层:ETag` 比对，不逐个文件派生密钥，私密空间也不逐个申请条目密钥（复用已有私密上下文）。明文标记只暴露「这个条目是用户手动缓存的」。预览中的单个文件仍用 `files` 消息（≤200）查询完整状态。`cancel` 释放当前任务，`remove-file` 在校验当前层级授权后清除指定内容版本。任务只存在内存，关闭／刷新页面主动取消，Worker 另有两分钟无进度的回收期限；重新打开后需手动继续，不依赖无限期后台执行。
- 私密任务需设备允许私密缓存，并在创建时解锁。点击缓存即建立任务，复用网页已有任务编号和登录会话，服务端只记录任务的文件／目录范围与设备缓存版本；不另发授权票据，没有独立的授权到期、续期或心跳。后续目录遍历和缓存读取根据登录会话与任务范围执行，内容流逐块复核，普通私密预览仍要求解锁。任务完成、移除或页面关闭后清理记录，异常关闭遗漏的记录在下次创建任务时按登录会话清理；没有数据库迁移。
- 锁定或私密闲置到期只撤销预览与普通缓存读取的私密上下文，已加入的文件夹遍历、排队和写入继续，任务与进度保留；Worker 的任务专用上下文仅用于缓存选定范围，不能给页面返回密钥或文件正文。锁定时本机缓存页隐藏私密名称、路径与具体错误，仍可查看进度、暂停、继续及删除任务记录；新任务和查看、清除私密副本仍需解锁。退出、关闭／刷新网页、关闭缓存设置仍停止任务，已提交密文按原有 TTL 和清理策略处理。缓存读取仍需登录与私密授权，不承诺离线访问。
- 视频自动缓存开关仅控制观看片段时的自动写入，用户手动缓存的视频仍可使用本机内容；Safari／iOS 的播放器兼容性仍需真机验证。

## 8.1 刷新后恢复任务队列

缓存任务的执行在页面里（`CacheTasksProvider` 逐个调用 Worker 的 `start`／`step`），页面关闭时任务停止，已写入的块保留。为了刷新后能继续，队列按账号保存：普通文件的任务记录（路径、ETag、大小、状态与进度）和仍在列出的普通文件夹存在 `localStorage` 的 `tessera:cache-jobs:<bucket_id>`；私密文件的路径不以明文写入浏览器存储（缓存条目里的名称也是加密的），私密部分交给 Worker，用 `HKDF(K_tier(私密), "tessera-cache-queue")` 派生的 AES-GCM 密钥加密（AAD `命名空间|queue`）后存在 IndexedDB `meta` 的 `private-queue/<命名空间>`。

- 恢复时进行中的任务回到排队，再由 Worker 只补缺失的块；私密记录只在解锁后读取，并用当前授权重新登记任务组（`/cache/tasks`）后继续。
- 锁定期间不写私密记录（保留上次的内容）；私密记录读取完成之前也不写入，避免空队列覆盖。改密码或重置缓存纪元后 K_tier 变化，旧记录解不开即删除。
- 退出登录或关闭本机缓存时删除记录；清除私密层或全部缓存时私密记录一起删除。

## 9. 预览预读（多段并行补齐自动缓存）

预览音视频时，页面调用 `cache-client.ts` 的 `startPreviewPrefetch`，向 Worker 发 `tessera-cache:prefetch`（预览编号、版本地址、播放位置字节），每 30 秒续期，拖动进度（跳动超过 15 秒）后带新位置再发，关闭预览或换文件时发 `tessera-cache:prefetch-stop`。Worker 端：

- 条目由播放器的第一次读取建立（`handle` 登记类型、大小与版本）；预读等条目出现（最多 20 秒）再开始，不自己登记，因此规则与自动缓存一致：未启用缓存、关闭自动缓存视频（视频且非手动）、本地目录未授权时不预读；单个文件最多占这一层容量的一半（手动缓存的文件可用满）。
- 从播放位置所在的块往后找缺失的块，到末尾后再从头补；每段不跨 16 MiB 分片边界，复用手动缓存的 `fetchSegment`（带 `X-Tessera-Background: cache`、严格写入）与 `manualSlot` 的共用并发上限（服务器读取路数减一，最多 3 路），服务器始终给播放保留一路。
- 停止：收到 `prefetch-stop`、60 秒没有续期（页面崩溃、标签页关闭）、文件补齐或达到单文件上限、文件已变化或连续 4 次临时失败、退出登录、更改设置或缓存目录。停止时中止进行中的请求，已写入的块保留。同时最多预读 2 个文件，超出时停掉最早的。
- 播放器自己的读取不等待预读，缺块照常回源；预读的价值在于让播放器跳着读的位置（分片 MP4 逐个片段读取 moof、拖动进度）多半已在缓存里。

回归：`tests/test_client_cache_worker.cjs` 的「预览预读」三项（补齐整个文件且带后台标记、从播放位置开始、关闭后立即中止）。
