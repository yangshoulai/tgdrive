# 浏览器本地缓存设计

目标：自动保留看过的图片、音乐、视频片段和缩略图，并允许用户手动缓存任意类型的完整文件，降低重复读取与 Telegram 流量；用户能查看、设置和清理；私密文件在锁定后即使拿到整个浏览器目录也无法解开。

## 1. 总体结构

```
页面 <img>/<video>/<audio>  ──►  Service Worker（/sw.js，作用域 /）
                                   │ 命中：从 IndexedDB 读密文块 → WebCrypto 解密 → 206/200
                                   │ 缺失：fetch(cache:'no-store') 回源 → 边转发边加密写块
                                   ▼
                              服务端 /api/user/v1/cache/*（只发密钥、做对账，不经手缓存数据）
```

- Service Worker 只处理带内容版本的 GET：`/api/user/v1/content`（`v`=ETag 且带 `bucket_id`）、`/api/user/v1/thumbnail`（`etag`+`v`）、以及对应的 `/api/user/v1/private/...`。内容预览统一携带版本；普通类型未手动缓存时直接回源，不自动建立条目。`download=1` 仅在本机已有完整条目时命中，否则直接回源且不写入缓存。其余请求不调用 `respondWith`。
- 自动读取出现异常时退回直接请求服务器；手动缓存必须报告写入错误，不能把仅完成网络接收当成缓存成功。浏览器不支持、用户或管理员关闭时正常文件访问仍可使用。
- 回源请求一律 `cache: 'no-store'`，浏览器 HTTP 缓存不再保存明文。私密响应（含私密缩略图）服务端改为 `no-store`。
- 存储使用 IndexedDB（所有平台的 Service Worker 都稳定可用）。数据按 1 MiB 分块稀疏保存，视频看过哪段存哪段；拖动时缓存块与回源片段拼成同一个连续响应。
- 上游请求绑定 `AbortController`：`<video>` 放弃请求时同步中止回源，不额外预读（与服务端渐进窗口的设计一致）。
- 缓存块缺失、损坏或本地存储读取失败时，删除坏条目，并从尚未交付的位置继续回源；已经返回给播放器的响应流不要求用户重新打开。首次 Range 回源按块对齐后，若版本变化或不能缓存，丢弃该响应并按原始 Range 重新请求。

## 2. 密钥

| 名称 | 位置 | 说明 |
|---|---|---|
| KEK | 服务端内存 | 系统主密钥，由加密口令派生，锁定即丢弃 |
| C（缓存主密钥） | `settings.client_cache.key` | 随机 32 字节，用 `derive_subkey(KEK, "client-cache")` 包裹；改口令时 `keystore.rotate` 只重新包裹 |
| K_tier | 服务端计算、浏览器内存 | `HMAC(C, tier‖层‖用户‖设备‖纪元‖sha256(密码哈希))`；普通层会话有效即下发，私密层需私密授权 |
| 条目基密钥 | 浏览器内存 | 普通层：`HKDF(K_tier, "entry|"+etag)`；私密层：服务端 `HMAC(C, entry‖…‖etag)` 逐个下发 |
| 条目编号／块密钥 | 浏览器内存 | 由条目基密钥按缓存版本（内容 ETag，或缩略图 `etag|规格|版本`）派生：编号 `HMAC`，块密钥 `HKDF` → AES-256-GCM |

- 密钥只存在 Service Worker 内存里，不落盘；Service Worker 被浏览器停止后重新获取（一次小请求）。
- 普通层的条目派生缓存属于当前层级密钥上下文，重新获取上下文后重新派生，不能跨纪元或密码版本复用。私密条目基密钥和块密钥不跨读取缓存，只合并同一授权上下文下当前并发批次的验权请求（每批不超过 500 项）。
- 设备编号是浏览器生成的随机串，存在 IndexedDB；同一账号不同设备密钥不同。
- 纪元在 `users.cache_epoch`（schema v26）。用户「重置所有设备的缓存」只需加一；改密码因密码哈希参与派生而自动失效。
- 命名空间 `HMAC(C, ns‖用户)` 区分同一浏览器里的不同账号，本地不出现账号 ID。

## 3. 本地数据

- `entries`：键 `命名空间/层/编号`；明文字段只有层、块序号列表、已存字节数、最后访问时间、普通层的大类（图片／视频／音频／缩略图／其他，供统计）；路径、类型、ETag、文件大小与手动缓存标记 `manual` 放在加密的 `info` 里。增加可选标记兼容现有 IndexedDB 结构，无需升级数据库。
- `blocks`：键 `条目键/块序号`，值为 `nonce(12) ‖ AES-GCM 密文 ‖ 标签`，AAD 为 `命名空间|层|编号|块序号`，块被调换或拼接会解密失败；解密失败即删除该条目并回源。
- 暴露的元数据：总占用、条目数、每个条目的大致大小与访问时间。私密层不记录大类。

## 4. 失效与删除

- 正确性：只有页面用最新列表里的 ETag 发起请求才会命中，已删除或被覆盖的文件不会被展示。
- 普通层对账：Service Worker 启动后、页面执行写操作后（防抖）以及每 15 分钟，把本地条目的 ETag 分批（≤500）交给 `POST /api/user/v1/cache/check`，只保留普通区（不含回收站、私密空间、系统区）仍引用的版本。
- 私密层：每次读取都要 `POST /api/user/v1/private/cache/keys`，私密区（不含私密回收站）不再引用的版本返回 null，浏览器删除；离线设备上残留的密文因拿不到密钥而无法解开。
- 401 只丢弃内存中的密钥，不删除数据（重新登录同一账号可继续使用）；解不开索引的条目（纪元或密码已变）在对账时删除。
- 私密条目超过 `private_ttl_days` 未访问即删除；锁定、退出、闲置到期时页面通知 Service Worker 丢弃私密密钥。
- 锁定、退出或重置通知同时撤销旧上下文，取消尚未交付的读取；通知前发出的密钥请求即使稍后成功，也不能恢复旧上下文或重新交付私密内容。

## 5. 策略

- 管理员（`/api/admin/v1/client-cache`，审计 `client_cache.update`）：`enabled`（默认开）、`max_mib`（每台设备普通层上限）、`entry_mib`（单个文件最多缓存的字节数）、`private_enabled`（默认关）、`private_max_mib`、`private_ttl_days`。
- 设备（用户设置 →「本机缓存」，存在 IndexedDB）：开关、上限（不超过管理员上限）、是否缓存视频（Safari／iOS 默认关闭）、是否在本机缓存私密文件（需管理员允许）、私密上限；查看占用与条目、按层清理、重置所有设备的缓存密钥（审计 `client_cache.reset`）。
- 超出上限按最后访问时间淘汰；开启时申请 `navigator.storage.persist()`。

## 6. 安全边界

- 服务端拒绝除 `/sw.js` 外所有带 `Service-Worker: script` 请求头的请求，用户上传的同源脚本不能被注册为常驻 Service Worker。
- `/sw.js` 地址固定，`Cache-Control: no-cache`。
- 挡不住的：解锁期间的 XSS、已经解密展示过的内容、正在播放的设备内存中的密钥（直到下一次对账或锁定）。
- iOS：ITP 可能在 7 天无交互后清除站点存储（添加到主屏幕的 Web App 例外）；Service Worker 回应 `<video>` 的 206 需要真机验证，因此 Safari 默认不缓存视频。

## 7. 回归验证

- `node --test tests/test_client_cache.cjs tests/test_client_cache_worker.cjs`：纯函数、加密、事务回滚，以及实际 Worker 的 fetch／message、逐读授权、撤销竞态、纪元更新、损坏块恢复、流取消、Range 降级和手动任务。Worker 测试用内存存储与服务端替身，响应流和加密使用原生实现；IndexedDB 与浏览器接管另做真实浏览器验证。
- `.venv-net/bin/python -m unittest tests.test_client_cache`：服务端密钥绑定、私密授权、对账范围、策略与脚本注册边界。

## 8. 手动缓存完整文件

- 文件列表以缓存按钮作为唯一快捷操作，分享仍在更多菜单；网格卡片和本人文件的预览头部提供相同入口。文件夹暂不递归缓存，公开访客与附件专用接口不参与。
- 状态为未缓存、部分缓存、排队、进行中、已缓存、失败。部分缓存显示比例并可继续；进行中点击展开「本机缓存」托盘；已缓存点击查看说明；移除仅放更多菜单，确认后删除本机副本。失败原因与重试、取消与继续均在托盘中提供。
- 页面外壳 `CacheTasksProvider` 维护内存队列，切换目录或普通页面继续执行。Worker 在所有标签页间只允许一个手动任务，以消息来源的客户端编号绑定任务；其他页面等待当前任务，不能用任务编号取消或推进别人的任务。
- `start` 消息重新取得策略，以 HEAD 校验权限、ETag 和大小；先检查单文件上限、设备／管理员层级容量与浏览器可用空间估计，再为完整大小预留空间，按 LRU 清理其他旧条目。活动条目受保护，但完成后仍参与正常淘汰，不提供永久固定。
- `step` 消息每次最多读取连续缺失的 8 MiB，沿用 1 MiB AES-GCM 数据块；每个块的 IndexedDB 事务提交后才通知页面进度。元信息更新不得覆盖并发预览写入的块列表；写入异常显式回滚整个事务，避免块索引提交却没有对应的数据。
- 进度以条目中已提交的逻辑字节为准，包含自动缓存或上次任务留下的块。全部块及总大小吻合后才视为完成，并再次 HEAD 复核当前版本。读不到完整响应、版本变化、配额不足、条目被清理均报告失败；取消立即中止回源，保留已提交部分。
- 页面使用 `files` 消息分批（≤200）查询可见文件，直接派生编号查询条目，不扫描所有本机文件。`cancel` 释放当前任务，`remove-file` 在校验当前层级授权后清除指定内容版本。任务只存在内存，关闭／刷新页面主动取消，Worker 另有两分钟无进度的回收期限；重新打开后需手动继续，不依赖无限期后台执行。
- 私密任务需管理员和设备允许，并且私密空间已解锁；每批补全重新申请条目密钥。锁定、退出或离开私密页面时中止并清除页面中的私密任务与文件名，密文块仍按原有 TTL 和清理策略处理。缓存访问仍需登录与服务端授权，不承诺离线访问。
- 视频自动缓存开关仅控制观看片段时的自动写入，用户手动缓存的视频仍可使用本机内容；Safari／iOS 的播放器兼容性仍需真机验证。
