# 书籍封面读取

新增电子书／漫画沿用现有封面流水线：写入提交后自动读取，保存列表小图、网格图和预览大图。历史文件不进入书籍补图；可在文件或媒体库的「编辑元数据 → 内置封面」手动读取，预览后点「保存封面」。读取本身不写入，原文件、ETag 和媒体库收录设置不改变。

| 格式 | 封面来源 |
| --- | --- |
| EPUB | EPUB 3 的 `cover-image`，兼容 EPUB 2 的封面标记和 guide 封面页；支持只引用一张本地位图的 XHTML／SVG 包装页 |
| MOBI、AZW、AZW3 | PalmDB／MOBI 的 EXTH 封面记录，原图优先，缩略图作为回退；兼容双格式文件的 KF8 头 |
| FB2 | `coverpage` 引用的 base64 `binary` 图片，流式解析正文而不保留正文树 |
| CBZ、CBR | `ComicInfo.xml` 中 `FrontCover` 标记；没有标记时使用图片文件名自然排序后的第一张，忽略隐藏项与 `__MACOSX` |

PDF 首页、TXT、Office、KFX／Topaz 不在本轮范围内。纯矢量 SVG 封面暂不渲染。加密、损坏、解压方式不兼容或超过读取上限会报告失败，可改用本地图片；不会将这些失败永久标记成「没有封面」。不尝试解除 DRM 或归档密码。

## 接入与依赖

- `media/book_covers.py` 是异步读取入口；`book_cover_worker.py` 是短时解析子进程。主进程只接受有界范围请求，逐段执行原有授权检查；解析后再次复核源文件版本和身份。超时或关闭请求时终止并回收子进程，不生成完整书籍临时文件，不访问书内外部链接。
- EPUB／CBZ 使用标准库 ZIP 索引与有界条目读取，支持存储／Deflate，只解封面和必要的描述文件。MOBI 按记录表定位图片；FB2 与部分固实 RAR 可能需要顺序扫描。单张图片最多 20 MiB，XML 描述最多 2 MiB，归档最多 50,000 项；单次解析累计范围读取最多 256 MiB、墙钟 55 秒。子进程 CPU 最多 30 秒，Linux 地址空间最多 256 MiB，全服务最多同时两个解析进程。
- CBR 使用系统 `libarchive`，在子进程中注册读取／跳转回调，不解压到文件系统。Docker 各运行变体安装 `libarchive-tools`；本机源码部署需自行安装该包或提供系统 libarchive。缺失库时明确提示，不影响其他格式。RAR 压缩方式与固实包兼容性取决于系统 libarchive。
- 新文件提交由 `ThumbnailService.enqueue` 登记 `book` 任务，优先复用 `ThumbnailCache` 中上传时已经交付的密文；不足时沿用提交任务的回源与资源评估。网页上传申请现有生成票据后调用 `/media/cover` 取原图，再在浏览器缩放，服务器没有 FFmpeg 也能完成网页上传封面。其他写入入口的后台缩放仍需要 FFmpeg。
- `observe` 不登记书籍，兜底补图 SQL 仍只查询图片／视频／音频。近期书籍的网页轮询仅查询封面状态，不触发读取；历史文件仅手动获取。已有封面、写入方指定封面以及用户手动封面继续优先。
- GET `/api/user/v1[/private]/media/cover?path=&etag=` 复用现有会话与私密授权，书籍读取不受在线媒体提供者的「内置数据」开关影响。保存沿用文件级封面资产、配额、票据与 ETag 校验，无 schema 变更，无历史数据迁移。

## 验证

`tests/test_book_covers.py` 使用内存样本与存储替身，覆盖格式定位、范围读取、自然排序、明确无图与失败的区别、恶意 XML／外部地址／越界路径、大小限制、源文件替换、授权撤销、取消及新旧文件触发边界；不连接数据库。
