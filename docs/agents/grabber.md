# 资源抓取脚本

给 AI 代理的模块细则（由根目录 AGENTS.md 索引）。userscripts/tessera-grabber.user.js：兼容层、iframe、批次、网盘取链与网盘文件夹。

- `userscripts/tessera-grabber.user.js`：资源抓取用户脚本，兼容 Tampermonkey／Violentmonkey（同步 `GM_*`）与 iOS Userscripts + Safari（只有异步 `GM.*` 和 `GM_xmlhttpRequest`，没有 `GM_cookie`、菜单命令；需要 `@inject-into content`）。所有 GM 调用都经顶部兼容层 `gm`（`gm.get/set` 读写启动时预读的内存缓存、`gm.openTab`、`gm.copy`、`gm.xhr`、`gm.menu`），不要再直接调用 `GM_*`；新增存储键时加进 `STORE_KEYS`。没有菜单命令时（`HAS_MENU` 为假）未启用的网站保留淡化悬浮按钮（`dormantFab`），窄屏面板以贴底的底部抽屉展开（`placePanel` 的 `is-sheet`），资源行只留「更多」与服务器下载，其余操作经 `openActionSheet` 在面板内弹出（同样登记在 `panel.layer`）；资源嗅探在观察器之外定时读取 `performance.getEntriesByType("resource")` 兜底。脚本不再声明 `@noframes`：iframe 里只运行 `frameAgent`（在启动段 `if (!IS_TOP)` 处提前返回，不注册菜单、不读写 GM 存储与设置、不挂界面），收到父窗口的 `frame-scan`（`FRAME_CHANNEL`，顶层启用时每 2 秒发一次，打开面板时带 `dom`）后才嗅探，并把自己与下级框架的资源以 `frame-items` 逐级交给父窗口；顶层 `onFrameItems` 只接受子框架（`fromChild`）的消息并经 `frameItem` 逐字段校验，停用时发 `frame-stop`。框架资源带 `referer`（框架页面地址）与 `frame`，curl 与浏览器读取用 `refererFor(url)` 取它。不要向框架发送设置、密钥或其他数据。（单文件、无构建步骤，界面放在封闭 Shadow DOM 中，一律用 DOM API 创建节点，不得使用 `innerHTML`／`DOMParser`／`eval`：YouTube 启用了 Trusted Types，这些调用会直接抛错导致脚本挂载失败）。只通过访问密钥调用 `/api/v1/downloads/parse`、批量解析 `/api/v1/downloads/parse-batch`（`parseEntries` 把非平台条目每 `PARSE_CHUNK`=20 个合成一个请求、两路并行，X／YouTube 逐个走 `parseEntry`；单项 `error` 只标红该行，`retry` 项用单项接口再解析一次；旧服务器返回 404 时 `parseBatchMissing` 退回逐个解析）、`/api/v1/downloads`、浏览器上传用的 `PUT /api/v1/files`、提交文件名用的 `POST /api/v1/move`、清理临时对象用的 `POST /api/v1/delete` 与目录选择用的 `GET/POST /api/v1/folders`（`KeyApi.folders` 只列一层、排除 `.tgdrive/`），不得依赖网页会话接口；保存到私密空间时脚本只解析，再用 `GM_openInTab` 打开 `/?view=downloads#import=<base64url JSON>`，由 Tessera 页面（`api.takeDownloadImport` + `DownloadDialog initial`）解锁并通过网页会话创建任务——不要为此给访问密钥开放私密空间，也不要在第三方页面里收集密码。选择层是面板内的覆盖层（`openPicker`，`panel.layer`），不得替换面板内容；生成的 curl 必须能被 `offline/request.py` 解析（bash 单引号，`'\''` 转义）。批量发送的进度来自 `GET /api/v1/downloads?ids=`（`OfflineDownloads.status_of`，只返回密钥所属用户、可读路径内的非私密任务）；轮询会频繁刷新的界面（批次横幅、进度行、底部按钮）必须原地更新节点，不能整块替换，否则会吞掉用户的点击；资源列表同样按地址复用行节点（`syncChildren`），按住鼠标期间暂停刷新。已发送记录存在 `GM_getValue("sent")`，只有任务创建成功或浏览器上传收到文件保存确认才写入，失败或停止时移除。浏览器上传优先网页 fetch（图片尝试缓存），跨域读取失败或网页 403 时再尝试一次 GM 请求；保持原始字节，拒绝 HTML／验证页面，单文件最多 64 MiB、一次只处理一个文件，只保存到普通授权目录；保存到私密空间时改为在点击事件里同步 `window.open` 打开 `/?view=private#receive=<nonce>&from=<来源 origin>`，下载好的 Blob 经 `postMessage` 交给 Tessera 页面（`web/src/user/transfer.ts` 只认 opener、来源与 nonce，`PrivateSpaceView` 解锁后交给 `FilesView incoming` → `UploadDialog`），文件不经过访问密钥。本地下载（`mode: "local"`）与服务器下载（`mode: "server"`）共用 `startBatch` → `renderBatch` 确认页：服务器下载打开时先 `parseEntries` 解析，每个分组替换成一行（`variants` 下拉、`candidate`、可改 `name`），开始后逐行 `createEntry`；确认页骨架按阶段只建一次、列表用 `syncChildren`，解析结果到达时不能重建输入框。普通资源的 GM 请求不要改写 User-Agent（网盘取链例外，见下条）；Cloudflare 验证（`challengeError`）只能由用户在标签页里通过，失败行提供「打开验证」。来源 Cookie 不转发到上传接口，Tessera 密钥不进入来源请求；确认页可编辑每项保存文件名，校验路径、控制字符、保留名、220 字节上限与批次重名；PUT 先写入自己随机临时名，再用 move（conflict=skip）提交到确认名，避免同名覆盖，失败后只清理自己的临时对象。同一条目重试沿用临时名，修改保存名后更新提交目标。已探测资源只在手动「清空」或刷新页面时清除：`collect` 把 DOM 扫描结果经 `remember` 存入 `items`（上限 `MAX_ITEMS`），`checkNavigation` 换页时不删除资源，新增清理路径前先确认用户意图。资源大小：`resourceMeta` 按地址缓存大小与图片尺寸，来源依次是资源计时（`timingSize`，仅图片／文件）、已加载图片的天然尺寸、视口内行的探测（`watchSize` → `pumpProbes`，`PROBE_LIMIT=3`，`requestSize` 先 HEAD 再 `Range: bytes=0-0`，读到响应头即中止）；探测失败或遇验证页面记为未知、不重试，结果经 `syncMeta` 原地更新行副标题（`describe`）。回归检查：`node --test tests/test_grabber.cjs`（`harness({ manager: "async" })` 模拟 Userscripts 环境，关键流程两种环境都要覆盖）。
- 网盘取链内置于抓取脚本的「内置网盘适配」区域，基于 LinkSwift 固定提交，出处、原始快照、函数映射与只读比对工具见 `third_party/linkswift/`。运行时仍是单文件，不加载快照或远程脚本。九个适配器读取网盘当前选择，异步 `cloudSources` 建快照，`parseEntries` 先用 `cloudResolveAll` 按 LinkSwift 的节奏批量取链（`CLOUD_PACE`：夸克／UC 每请求 15 个 fid、百度自盘 50 个 fsid、阿里 3 路并行、其余 15 路并行、百度分享逐个，批间停 `CLOUD_PAUSE` 1 秒；多文件请求失败时逐个重试），`parsePayload` 等待各自的直链，再经 curl 文本交给批量解析与创建接口；网盘里勾选的文件夹见下文「网盘文件夹」；勾选的文件即使之前发送过（`isSent`）也全部进入确认页，标「已发送过」（`resent`）并提示，可移除，不能静默跳过或整批拦下；网盘文件与网页资源的勾选数量都不设上限（页面快照不截断，网页资源列表也不再有 50 项的勾选上限），批次可以并行：`batch` 是面板正在查看的批次，`batches` 是已开始、仍在跟踪的全部批次（`runBatch` 开始时登记，`clearBatch(current)` 移除），运行中的循环用 `batchAlive(current)` 判断是否继续，不要改回 `batch === current`（否则开始新批次会让旧批次停下）；`startBatch` 不再拦截进行中的批次，只清掉已结束的记录并跳过正在其他批次里处理的地址，`poll` 遍历全部批次，主面板每批一条横幅（`bannerFor`，节点按批次复用），本地下载跨批次经 `localTurn` 依次处理。`startBatch` 按 `batchLimit()`（设置项「每批文件数」，存储键沿用 `cloudBatch`，网盘与网页资源共用，默认 `BATCH_DEFAULT`=100，上限 `BATCH_MAX`=500，非法值按默认：一批取链与解析都完成才创建任务，批太大时前面的直链与解析票据（`offline/service.py` 的 `TICKET_TTL`，30 分钟）会过期，不要随意调大上限）自动分批，批大小在开始时记入 `batch.limit`，`nextRound` 沿用它：确认页只放第一批（`batch.entries`），其余存 `batch.deferred`（`round`／`rounds`／`archivedOk`）；`runBatch` 创建完一批后 `nextRound` 把已完成的行收起为 `archivedOk` 计数、取下一批（`autoRound` 行解析后直接 waiting）并 `runBatch(true)`（跳过改名检查；本地上传模式不解析，`nextRound` 在调用 `runBatch` 前没有 await，私密空间「发送下一批」的点击里才能同步打开 Tessera 标签页），直链与解析票据都会过期，不要改成一次取完全部；私密空间每批要在 Tessera 页面确认，下一批等用户点「发送下一批」；`dropRounds` 放弃未开始的批次；`batchDone`／`batchSummary` 计入 `deferred` 与 `archivedOk`，轮询 `?ids=` 每次最多 200 个；重试重新取链并保留修改名。`@inject-into content` 下不能假定 `unsafeWindow` 可访问 React／Vue 状态；`cloudReadSelection` 是可独立运行的只读函数，必要时经 `gm.pageScript`（优先 `GM_addElement`，否则 DOM 创建）把白名单文件字段放进临时脚本节点的 DOM 属性，读完立即移除；不得向页面桥接 GM、Tessera 配置／密钥或通用执行能力。阿里自盘支持列表／网格，阿里、移动和迅雷分享页只给转存说明与「打开我的网盘」。网盘取链请求与 LinkSwift 一致使用客户端身份（`CLOUD_API_HEADERS`：百度自盘 `pan.baidu.com`，夸克／UC／123 为 PC 客户端 UA 与 `Sec-Ch-Ua`，其余保持浏览器 UA），Origin／Referer 为网盘站点；`cloudRequest` 对非 2xx 也解析 JSON，错误经 `cloudFailure(context, code, message)` 显示服务商的代码与说明（「服务器说」），已知代码按上游给出具体提示（夸克／UC 31001、23018，百度 112／9019，阿里 AccessTokenInvalid，天翼 InvalidSessionKey／ShareNotFoundFlatDir，光鸭 9／103／207，123 5112／5113）。普通网页资源的 GM 请求仍不改 UA；下载 UA 照旧只交服务器；来源凭据不进入上传请求，Tessera 密钥不进入来源请求。合并脚本自 0.16.0 起按 AGPL-3.0-or-later 发布，`userscripts/LICENSE`／`NOTICE.md` 与内嵌声明保留完整许可，后端及独立网页仍 MIT。更新适配器时同步来源版本、快照校验值、版权说明与脚本版本，并覆盖同步／异步 GM 的选中文件、签名、分享与凭据隔离回归；`harness({ isolated: true })` 将页面与脚本放在不同 VM 中，不能只测同一环境的假 DOM。
- 网盘文件夹（抓取脚本「内置网盘适配」）：勾选里有文件夹时 `cloudSources` 经 `cloudFolderLister` 选列表函数（`cloudListBaidu` 自盘 xpan／分享 share/list、`cloudListQuarkUc` file/sort／sharepage/detail、`cloudListAliyun`、`cloudList123`、`cloudListTelecom`、`cloudListXunlei`；移动、光鸭返回 null → 提示打开文件夹选文件），`cloudListTree` 逐层列出建树（不设数量上限，每 50 次列表停 3 秒），`openCloudTree` 在面板覆盖层里以树形挑选（默认全选、三态复选框、行按需创建，每次只渲染 `CLOUD_TREE_PAGE`=200 行，「再显示」继续），`cloudPickedFiles` 给每个文件带 `__folder`（以所选文件夹名开头，经 `cloudFolderSegment` 清理）→ 条目 `folder` → 创建任务时 `items[].folder`（私密转交同样带上，网页 `DownloadDialog` 原样提交）。同名检查按「folder + 名称」。服务端 `OfflineDownloads.create` 的 `folder` 经 `normalize_user_path(directory=True)` 拼在保存位置后，记住的保存位置不含子目录（`tests/test_offline_folder.py`）。测试里 `cloudTreePicker` 被替换为不经界面的挑选（`setPickTree`）。列表接口未在真实网盘逐一验证，改动时以网盘实际返回为准。

- 0.23.0：面板配色与 Tessera 网页一致（主按钮墨色 `--primary`，强调色 `#3550d4`／深色 `#8b9cff`，去掉渐变与光晕），行内的「服务器下载」平时是低调图标、悬停或选中行时才用强调色。宽或高小于 `SMALL_IMAGE`（200px）的图片默认隐藏（设置 `hideSmall`，筛选行的「显示 N 张小图」切换；已勾选的小图仍显示）。面板快捷键（焦点在面板内且不在输入框）：A 全选、V 切换视图、⌘／Ctrl+Enter 服务器下载已勾选的资源。
