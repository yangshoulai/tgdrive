# 文件助手

给 AI 代理的模块细则（由根目录 AGENTS.md 索引）。Agent 循环、工具、确认坞、长任务、识图与附件、本机缓存工具、私密对话、思考程度、P5、媒体与文本工具。

- 文件助手的提问、文件操作、范围请求与 HTTP 审批由 `web/src/user/assistant-review.tsx` 统一放在输入框上方的确认坞（默认紧凑、可收起，新请求自动展开），按队列逐项处理，决定后移除；消息流里这些请求是过程时间线中的决定节点（`assistant-thread.tsx` 的 `DecisionStep`，经 `DecisionContext` 取操作状态，「去处理」经 `onReview` 定位确认坞），不另起结果卡片，也不提供撤销入口；计划在消息中只占一行，「继续」只在顶部计划栏。见 `docs/assistant-design.md` §31。长任务分段续跑（`config.LIMITS["auto_continue"]`，`_run` 中按段重置预算）与计划「说明依据后完成」（`planning.py` 的 `unverified`、`brief`）见 §32。工具之间的说明仍是时间线的 note 节点，使用消息图标、「进度说明」与一行摘要；实际 reasoning 使用大脑图标与「思考中」／「思考」，正文默认收起，展开与滚动选择限定在本轮，最终回复独立展示。OpenAI 渠道的 protocol 可选 responses（配置存 assistant.channel.<id>.protocol），请求官方思考摘要并保留同一模型与凭据绑定的加密续接项 _responses；此内部字段不得进入网页、SSE、导出或日志，可见思考正文不回传模型；`assistant-thread.tsx` 的 `group` 只把一轮最后、之后没有步骤的无工具回复当作最终回复（`answerAt`），被续跑取代的回复放回原位；结束语承诺「会继续」却没有待处理操作时由 `_CONTINUE_PROMISE` 触发一次 `continue_check`（§32）。补充要求先拒绝旧请求、停止原运行，再作为新消息重新规划，不能修改或同时批准冻结参数。普通／私密操作有效期共用 `config.ACTION_TTL`（24 小时），HTTP 审批为 `HTTP_APPROVAL_TIMEOUT`（30 分钟），人工等待不占工具及整轮执行预算；登录与私密授权按原规则失效。见 `docs/assistant-design.md` §28。
- 助手执行链路见 `docs/assistant-design.md` §30：HTTP 不再暴露 `max_bytes` 或独立响应上限，按 `tool_result_bytes` 分段并用 `next_offset` 继续；`inspect_page` 提供通用 HTML 结构，`analyze_page` 保留相册规则。私密授权由 `PrivateSpace.assistant_busy` 按同一授权的真实执行续期，人工等待不续期，撤销后不能恢复。文件操作确认结束后只续跑最新等待任务；待确认队列满 128 项拒绝新建，不让旧请求静默过期。
- 长任务见 `docs/assistant-design.md` §38：`update_plan` 的 `notes`（≤2000 字）每步进入上下文块，是跨裁剪的进度记录；裁剪后的摘要行带 `ref` 与保留字段（`service._KEPT_FIELDS`），`recall_result` 只读本对话留痕、不重新执行；重复检测按（工具、参数、结果哈希），首次超限写 `repeat_check` 提醒，同段再超限才停止，不要改回按参数计数或直接停止。多层网页用 `collect_links`（链接结果集）→ `collect_gallery(albums=…)`（进度存 rule 的 `batch`，可续跑，相册内只走学到的翻页规则）→ `propose_downloads` 的 `offset`/`limit`、`by_album`（执行器按子目录分组并逐个复核作用域）。回归：`tests/test_assistant_longtask.py`。
- 文件助手（`src/tgdrive/assistant/`，设计见 `docs/assistant-design.md`）：管理员只能看到对话元数据，管理端接口与 `admin_*` 方法不得解密标题、消息、工具参数或结果；正文用 `assistant.trace_key`（KEK 子密钥包裹，改口令时在 `keystore.rotate` 重新包裹）加密，渠道 API Key 与请求头用子密钥 `ai-channel-key` 加密，接口只返回掩码。工具路径对模型一律是 `/` 开头的桶内路径，经 `ToolContext.resolve` 限制在对话作用域内，拒绝 `.tgdrive/` 与私密空间；扩大作用域只能经 `request_scope` 生成的 `assistant_actions`（`kind='scope'`）由同一登录会话带 CSRF 确认。新增工具在 `tools.py` 用 `@tool` 注册（级别、分组、参数上限），只读工具不得写入；以后的写入工具只能生成待确认操作，不能直接改文件。Agent 循环每一步都重新检查系统锁定、会话、账号与助手／模型开关，上限在 `config.LIMITS`（含硬上限）。调用日志 `assistant_calls` 只记元数据（错误经 `providers.scrub` 脱敏），不进入备份。渠道请求用 `providers.py` 自带的 HTTP 客户端，不经 `SafeHttpClient`（渠道地址只能由管理员配置）。公共使用知识 `knowledge.HELP` 是用户文档站的精简版，链接必须指向 `docs-content.tsx` 中存在的页面，修改文档的步骤或接口时同步更新；只放用户文档与公开地址，不放管理员文档或部署信息。`http_request` 是受控接口请求（设计 §20.1）：普通对话支持常用方法、查询参数、通用头与正文；审批模式下的非安全方法、正文和认证经同一会话的 `http_request_approval` 聊天卡片确认；完全访问下常规请求自动发送，HTTP DELETE 始终确认，再复核权限并发送冻结参数；不使用页面弹窗，确认决定与执行结果随加密工具消息保留。所有连接经 `SafeHttpClient`，禁止内网、连接级头和系统凭据；第三方响应凭据使用本轮同源内存引用，不进入模型正文。工具设为交互类，管理员可关闭高级请求及调整跨对话分钟额度／每轮次数／请求体大小与统一工具结果预算，每用户 2 路、全站 8 路；带正文或认证的请求不自动重放或跳转。结果视为不可信数据（`TAINT_TOOLS`）；只有无认证、无自定义头的 GET 二进制响应生成下载结果集。普通和私密对话均支持任务所需的公共地址、跨站链接、正文、第三方认证和查询参数；HTTP 文本响应可按 offset/next_offset 分段继续读取。客户端环境只接受 `client_environment` 校验过的低熵字段，不参与授权。默认使用说明涉及的数据范围变化时更新 `config.DEFAULT_NOTICE_SINCE`，让旧确认失效。发送接口的 `scope: "path"`/`scope_path` 与 `mentions` 只接受普通文件区域内的路径（`_location`、`_mentions`），引用必须在作用域内且存在；界面负责先扩大作用域。输入框是 CodeMirror 6（`web/src/composer-engine.ts`，与预览引擎一样由 `build-apps.mjs` 单独打包为 `composer-<hash>.js`，`preview-runtime.ts` 的 `loadComposerEngine` 在打开助手时加载），宿主是 `user/assistant-composer.tsx`（加载前或失败时退回普通 textarea）：文档始终是 Markdown 纯文本，只用装饰隐藏标记、把已选中的 `@/路径` 换成原子胶囊（图标克隆自隐藏的 `FileGlyph` 模板）、给网址加地球图标；列表续写与发送在引擎的 keymap 里。不要改成富文本 DOM 模型，发送内容与服务端校验都依赖纯文本。消息重试走 `retry`（`trace.truncate` 删除该条及之后的消息并让这些运行的待确认操作过期），不要在前端重新发送同一文本。上下文（设计 §23）：`_context` 依次做旧工具结果瘦身（早于最近两轮只发 `_slim_result` 摘要行）、按「上次实际 input_tokens + 估算增量」（`_measure`，实际值不到估算四分之一视为不可信）判断 70% 触发模型摘要、超过 85% 用 `_shrink` 把本轮较早的工具结果换成摘要行，仍超出抛 `ContextFull` 结束本轮；渠道 `context_overflow`（`providers.is_overflow`）强制压缩并重试一次。估算包含系统提示词与工具定义；`_history` 带的 `_run`／`_slim` 内部字段经 `_clean` 去掉后才发给渠道；每条助手消息记录 `prompt_estimate`，对话详情与 SSE `context` 事件给出占用。抽屉的 Esc 在 window 捕获阶段处理，抽屉内新增对话框要加 `assistant-dialog` 类，否则 Esc 会先关掉抽屉。头像 `AssistantMark` 的动效状态由 `useMarkState` 给出（工具状态至少保持 1.4 秒），不要在组件里直接按 `live.phase` 切换。下载对话（设计 §39，`assistant/export.py`，`GET .../conversations/<id>/export?format=markdown|json&tz=`）只给对话所有者本人明文，内容范围与对话详情一致（去掉 `model_content`／`model_text`／图片等 `_HIDDEN` 字段），私密对话走 `_check_private`（423 时前端解锁后自动重下），审计只记格式与消息数；管理端不得提供导出。`_send` 遇到 bytes 结果原样发送。回归：`tests/test_assistant.py`、`tests/test_assistant_export.py`、`tests/test_assistant_providers.py`、`tests/test_assistant_actions.py`、`tests/test_assistant_catalog.py`、`tests/test_assistant_p5.py`、`tests/test_assistant_context.py`。
- 文件助手识图与附件（设计 §22）：模型是否支持图片输入只看 `capabilities.vision is True`（`ChannelStore.vision`），管理员手动值记在 `manual_fields` 的 `vision`，`CatalogStore.apply` 同步时保留。图片经 `assistant/vision.py` 的 `load_image` 读取：优先浏览器生成的 `poster` 预览图，否则只发送上限内的 JPEG／PNG／WebP／GIF 原图，类型按文件头判定，服务端不解码图片。`_history` 只给当前这一轮（`run_id`）的用户消息与 `view_image` 结果加 `image_refs`，由 `_attach_images` 读取（`RunState.images` 缓存）；更早轮次换成文字占位，留痕只存路径不存图片字节，`_estimate` 每张图按固定 token 计。OpenAI 兼容格式下 `view_image` 的图片在整批工具结果之后合并成一条用户消息，Anthropic 放进 `tool_result` 数组。聊天框附件是独立模块「对话附件」（§22.5，`assistant/attachments.py` 的 `AttachmentStore` 是唯一写入／删除入口）：对象存于系统区 `.tgdrive/assistant/<附件ID>/<文件名>`，登记在 `assistant_attachments`（schema v22），计入配额、不出现在我的文件、网页文件接口／访问密钥／S3 不可访问。上传与读取走 `/api/user/v1/assistant/attachments`（`PUT ?name=`、`<id>/content|thumbnail|thumbnails|discard|save`、`stats`），发送接口的 `attachments` 是附件 ID，`bind` 绑定到消息并在对话内按「名称 (2)」去重；未发送的可 `discard`，已发送的只随对话删除（`delete_conversation`、重试 `delete_after`、`service.cleanup` 在保留期清理对话前先删附件、`purge_all`、维护任务清理 2 小时未发送与残留）；关闭抽屉、新建对话、页面卸载（`pagehide` + keepalive）时前端放弃托盘中未发送的附件，设置可 `discard-pending`。新增删除对话的路径必须同时删除附件。模型只见 `附件:显示名`：`ToolContext.attachments`（显示名→键）仅在 `read_only` 时由 `resolve`／`scope_for` 放行，`display` 反向映射，写入工具收到时报错；交给模型的图片标签、错误文案都不得出现 `.tgdrive/` 路径（`load_image(label=...)`）。另存为普通文件用 `ObjectService.link_copy`（引用同一 Blob），入口为网页 `save`（审计 `assistant.attachment.save` 只记大小）与写入工具 `propose_save_attachment`（`kind='save_attachment'`，可撤销）。已用空间分项 `GET /api/user/v1/usage`（侧栏「已用空间」展开，分「用户数据」：我的文件／回收站／私密空间，与「系统数据」：缩略图／助手附件）。查看图片属于读取外部内容（`TAINT_TOOLS` 含 `view_image`）。助手抽屉放在 `PreviewHost` 内，消息里的附件图片直接打开预览。回归：`tests/test_assistant_vision.py`、`tests/test_assistant_attachments.py`。
- 文件助手本机缓存工具（设计 §26）：缓存只在浏览器里，服务端只列出作用域内文件。`ui_cache_status` 是实时工具，抽屉用缓存队列的 `report`（重新读取 SW 缓存索引）回答，服务端只保留自己发出的路径；`ui_cache_files`／`ui_clear_cache` 只生成 `cache`／`uncache` 卡片（`assistant-thread.tsx` 的 `CacheBrowserCard`），审批模式点击后经 `enqueueMany`／`forget` 执行；完全访问经同一会话的浏览器桥接自动执行并回传实际结果，设备信任和私密解锁要求不变。
- 文件助手统一对话与私密空间（设计 §37 替代 §24 的独立私密对话，schema v28：`assistant_conversations.private`／`private_at`；另有 v25 的 `ai_models.private_ok`、`ai_user_policy.private`／`private_notice_ack_at`、`assistant_calls.private`）：只有一个助手，私密对话与普通对话一样存入对话表、加密留痕并进入备份。对话一旦涉及私密（在私密空间页面新建、`mentions` 含 `私密:/`、或工具首次作用于私密路径）由 `trace.mark_private` 永久标记并在消息流写 `private` 事件；此后详情、发送、重试、事件流、确认操作都要求当前登录会话已解锁（`_check_private` → `PrivateLocked`，HTTP 423 `private_locked`，前端弹解锁而不登出），列表锁定时 `title=None`、`locked=True`，删除不需要解锁。私密授权一律取自服务端 `PrivateSpace.session_grants[会话]`（`_session_access`），不再由请求携带 `X-Private-Access`；运行记录本轮使用的 `access`，`PrivateSpace.listeners` → `on_private_forget` 取消持有该授权的私密运行（停止原因 `private_locked`）与私密操作（可能来自工作线程，经 `call_soon_threadsafe`），对话保留；续期 `private_busy` 只认涉及私密的运行与 `_private_actions` 中的操作，人工等待不续期。模型看到的私密路径统一写作 `私密:/路径`（`tools.display_key`／`key_of`），`call_area` 按 `PATH_KEYS`、`match`／`mapping` 与 `area` 参数判断每次调用的区域并去掉前缀，同一次调用不能跨区；进入私密区域经 `_private_call` 依次检查 `private_enabled`、账号可用、模型 `private_ok`（否则 ToolError）、私密说明（否则 `PrivateRequired("notice")`）与解锁（否则 `PrivateRequired("locked")`），`PrivateRequired` 结束本轮并发 `private_required` 事件，前端解锁或确认后自动发送一条继续消息。工具规则仍在 `tools.py` 的 `PRIVATE` 表（含义改为「能否作用于私密路径」），`ToolSpec.area`／`area_skip` 固定区域（`propose_move_out` 只接受私密源、`propose_move_to_private` 只接受普通源，target 跳过检测）；`ctx.hide()` 按区域过滤系统区，不要再写 `substr(key,1,9)!='.tgdrive/'`。调用日志：涉及私密的对话不记工具执行，其余调用清空对话／运行／工具字段并记 `private=1`；管理端只看到私密标记，`admin_conversation` 不返回工具名。跨区移动都在 `CONFIRM_KINDS`，移出当场验证密码或通行密钥，审计 `private.assistant.move_out|move_in`；移入可由模型给出 `私密:/` 目标（存为相对路径作卡片默认值）。`/api/user/v1/private/assistant/*` 已删除。前端只挂一个抽屉：`detail.conversation.private` 决定私密标记与 FAB 锁形角标，`assistant-api.ts` 的 `UNLOCK_EVENT` 在 423 时通知抽屉弹出 `UnlockDialog`（复用 `PrivateUnlockForm`），授权从有到无时关闭私密对话并收起抽屉。回归：`tests/test_assistant_private.py`。
