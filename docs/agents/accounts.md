# 账号、分享与私密空间

给 AI 代理的模块细则（由根目录 AGENTS.md 索引）。公开分享与转存、公开链接令牌、访客注册、账号资料、私密空间。

- 文件夹也能公开：分享信息（令牌、有效期、密码、下载次数）保存在文件夹的**目录标记行**（以 `/` 结尾的对象）上，没有标记的隐式文件夹在分享时补一个。访客只读：`/s/<令牌>` 浏览（`?path=` 为相对路径），`/api/public/v1/folders/<令牌>/list` 列目录，`/p/<令牌>/<相对路径>` 读取文件；相对路径必须经 `ObjectService._public_relative` 校验，不得越出被分享的目录。重写目录标记（新建同名文件夹、移入回收站）时必须保留这些列，不能用新行覆盖。
- 保存他人分享（`ObjectService.save_public`，网页入口 `/api/user/v1/shares/<令牌>/status|save`）：新对象直接引用来源 Blob（增加 refcount、计入保存者配额），不得复制来源的公开分享列；整个保存在一个事务内完成，相对路径必须经 `_public_relative` 校验；分享者本人保存返回 400，密码分享由路由层用 `share_access` 校验。
- 公开链接令牌存放在 `objects.public_token`：覆盖写入在 `_commit_blob` 中继承，移动随行保留；禁用账号或锁定系统时 `/p/` 不可访问。新增改写对象行的代码路径时需要保持这一语义。
- 访客注册（`registration.py`／`mailer.py`，schema v27）：默认关闭，配置入口 `/admin/settings?tab=registration`，公共网页接口 `/api/auth/v1/registration`、`/registration/code`、`/register`。邮箱验证码与邀请码可单独或同时开放，同时开放时任选其一；邀请码单次核销与账号创建必须同事务。SMTP 密码和邀请码用 `registration-secret` 子密钥加密，改系统口令时在 `keystore.rotate` 一起重加密；验证码仅在内存中保留 HMAC 摘要。邀请链接用 `/register#invite=…`，前端只读固定邀请码，禁止把邀请码、验证码、SMTP 密码写入审计。邮件发送强制 TLS；测试必须替身发送，不得连接真实 SMTP。
- 账号资料（schema v19）：`users.username` 是登录邮箱，新账号经 `accounts.normalize_email` 校验并转小写，旧的非邮箱用户名保留并以 `needs_email` 标记，前端登录后强制设置邮箱；昵称在 `users.nickname`，头像在 `user_avatars`（随账号级联删除，进入备份）。改邮箱走 `AccountService.change_email`（确认密码 + `SessionManager.rename_user`），不要直接 UPDATE username。界面显示名统一用 `api.displayName`；公开分享页只通过 `AccountService.sharer` 展示昵称和头像，没有昵称时不显示，绝不能暴露邮箱。头像地址用 `api.avatarUrl` / `api.adminAvatarUrl`。后续邮箱验证码应接在 `change_email` 与新建账号流程上。
- 私密空间由 `private.py` 管理短期授权，使用账号当前登录密码或账号通行密钥，授权绑定会话、账号和密码版本，网页入口为 `/api/user/v1/private/`。闲置时间按用户保存在 `private_spaces.idle_seconds`，未设置默认 1800 秒，可选 300／900／1800／3600／5400／7200 秒（`IDLE_OPTIONS`，与前端 `PRIVATE_IDLE_MINUTES` 一致；v29 把旧的 60 秒改为 300 秒，v31 同步扩展数据库 CHECK 约束）；设置通过普通会话与 CSRF 调整自己的时间，不允许客户端指定其他用户。保存会撤销本账号旧私密授权与待验证解锁；当前会话已有有效授权时重新签发，未解锁时不签发。不存在管理员统一策略。同一普通会话共享一个授权，`/status` 可以恢复有效授权，空闲时不续期，助手执行中按 §30 保持解锁；前端 `user/private-session.ts` 的 Provider 挂在应用外壳，切页、刷新和新标签页不主动撤销授权，离开私密页面仍关闭私密预览；私密上传可从任何页面的上传弹窗发起，锁定时由应用外壳（`user.tsx` 监听 `tessera:private-locked`）统一取消。解锁表单 `PrivateUnlockForm` 与弹窗 `PrivateUnlockDialog` 在 `user/private-unlock.tsx`（位置选择器 `folders.tsx` 也用它，放在 `private-access.tsx` 会形成循环导入）；所有需要解锁的地方（私密空间页、移入移出、离线下载保存到私密目录、位置选择器、本机缓存、文件助手）都弹出 `PrivateUnlockDialog`，不要在页面或其他弹窗里直接内嵌 `PrivateUnlockForm`；解锁成功时调用方的界面常会立刻卸载弹窗，回调可能来不及触发，调用方要在授权出现时自行收起解锁状态；`FolderPicker` 的 `allowPrivate` 在未解锁时点「私密空间」弹出解锁，只能在 PrivateSessionProvider 内使用。手动锁定撤销该登录会话的全部私密授权与待验证解锁；退出、改密、禁用、系统锁定及重启使授权失效。凭据在设置中统一管理，接口为 `/api/auth/v1/passkeys`；未登录验签绑定固定来源和短期 HttpOnly Cookie，已登录敏感操作要求 CSRF 及登录密码确认。`Scope.private_access` 默认关闭，普通网页、管理文件、访问密钥和 S3 不得绕过 `.tgdrive/private/` 与 `.tgdrive/private-trash/` 的保护；内部账号删除和过期回收站维护可以显式授权。新增私密读取需禁用持久缓存（唯一例外：`GET /private/thumbnail` 成功时按版本长期私有缓存，地址不带 access，授权取 `session_grants[会话]`），异步写入提交前及文件流逐块重新校验授权，移入必须递归取消公开链接。

- 资源抓取脚本的私密授权由 `private_keys.py` 对接 `/api/v1/private/`：只有所属用户自己存储桶的根目录 rw 密钥可以发起，另需当前脚本安装的随机标识与密码或通行密钥验证；内部短期会话按「访问密钥 + 脚本安装」隔离，不签发 Cookie、不返回网页 token/CSRF，与主站登录会话独立。复用 PrivateSpace 的闲置设置和撤销规则，status 不续期，私密交互续期；实际流式写入及提交重验密钥和授权。密码仅在 Tessera 来源的独立解锁页输入，普通访问密钥与 S3 路径仍拒绝私密空间。详见 [grabber.md](grabber.md)。

- 公开文件、文件夹、歌单的元数据资源按源分享校验密码、有效期、账号和当前引用，隐藏路径不公开。私密资源异步读取后再次复核授权。 详见 [文件级元数据](../media-metadata.md)。
