# Telegram 交互机器人、星标与歌单

## Telegram 交互机器人（`src/tgdrive/telegram/bot.py`，schema v41 `telegram_links`）

- 与存储通道分开：管理员在「存储通道」页底部的「Telegram 机器人」面板填一个**新的** Bot token（`POST /api/admin/v1/telegram-bot`，`/telegram-bot/delete` 删除）。token 用子密钥 `telegram-bot-token`、aad `telegram-interaction-bot` 加密存 `settings.telegram.bot.token`，`keystore.rotate` 同步重加密；存储通道正在用的 Bot（按 token 冒号前的编号比对）会被拒绝。保存时 `getMe` 校验、`deleteWebhook`、`setMyCommands`；换成另一个 Bot 时清空 `telegram.bot.offset`。审计只记 `token_changed` 与启用状态。
- 收消息用 `getUpdates` 长轮询（`InteractionBot._poll`，在 ASGI lifespan 启停，单进程部署，不需要公网地址）；每批处理前先写 offset，避免重启后重复执行。系统锁定、未配置或停用时不轮询，`client()` 不在内存里保留 token。409（另一个程序在收消息）、401 写入 `last_error`，控制台面板显示。
- 绑定：用户在「设置 → Telegram」调用 `POST /api/user/v1/telegram/link` 得到 `t.me/<bot>?start=<code>`，绑定码只在进程内存、10 分钟有效、一次性；`/start <code>` 写入 `telegram_links`（一个账号一个私聊，一个私聊只属于一个账号；用户删除时级联删除）。私聊里 `/unbind` 或网页 `/telegram/unlink` 解绑；绑定与解绑写审计。只响应 `chat.type == "private"`，群组忽略。账号停用、系统锁定时只回提示。
- 消息路由（`_message`）：命令（/help /status /folder /notify /ask /new /unbind）→ 带文件（document／photo 取最大尺寸／video／audio／voice／animation／video_note）保存到 `telegram_links.folder`（官方 Bot API 上限 20 MB，自建服务上限 2000 MB；收到的文件统一按保存时的毫秒时间戳 + 小写扩展名命名，同毫秒递增 `_file_timestamp`，扩展名优先原文件名、缺失时按 MIME 补齐、未知时 `.bin`，保留 `.tar.gz/.tar.bz2/.tar.xz` 复合扩展名；仍以 `_free_name` 避免与已有文件重名；同一 `media_group_id` 攒 2 秒合并回复）→ 含 `http(s)://` 或以 `curl ` 开头的文字走 `OfflineDownloads.parse(multiple_platforms=True)` + `create`，同一 `group` 的候选按 `_variant_score`（分辨率、码率）选最高的一个 → 其余文字转给文件助手。消息里有链接又想问助手时用 `/ask`。
- 文件助手：机器人为账号建一个内存会话（`sessions.create`，12 小时，过期或改密码、禁用后重建），对话编号存 `telegram_links.conversation_id`（私密对话不复用）。`AssistantService.send(..., channel="telegram")` 让 `RunState.channel = "telegram"`：去掉 `group == "browser"` 的工具，上下文块的「用户所在页面」换成 `prompts.TELEGRAM_VIEW`；确认后继续的运行沿用同一会话上一轮的 channel。回复取本轮最后一条 assistant 消息，`markdown_html` 转成 Telegram HTML 子集（400 解析失败时退回纯文本），按 4000 字切分。本轮新建、待确认的操作（`assistant_actions.run_id`）逐个发「确认／拒绝」按钮（`callback_data = a:<id>:y|n`），回调里用同一个机器人会话调用 `decide_action`（`acknowledge` 由按钮表示），之后等操作结束并转发继续运行的回复或执行结果。操作卡片绑定发起它的会话：机器人会话重建后旧卡片会提示过期。
- 自建 Bot API（`docker-compose.yml` 的 `bot-api` profile，镜像 `aiogram/telegram-bot-api`，`TELEGRAM_LOCAL=1`）：Bot API 地址与文件目录按「控制台设置（`telegram.bot.info` 的 `api_url`／`files_dir`，`api_url` 为空串表示明确用官方）> 启动参数 `TGDRIVE_TELEGRAM_BOT_API_URL`／`_DIR` > 官方」生效。切换服务时 `_switch_server` 先在原服务上 `logOut`（换回官方后约 10 分钟不能登录）。自建模式下单个文件上限 2000 MB，`getFile` 返回服务器上的绝对路径，`_local_path` 只允许 `files_dir` 之内（两容器挂载同一数据卷到 `/var/lib/telegram-bot-api`），`_read_local` 1 MiB 分块边读边 `put_object`，保存后删除；自建客户端用单独的 `PooledTransport(timeout=3600)`（getFile 要等整个文件下完）。超过 20 MB 的文件在后台处理（不占私聊锁），`_imports` 名额等于「下载与资源」的离线下载同时下载数（`resources.effective()['concurrency']`，按机器自动），开始前按 `files_dir` 磁盘剩余空间减已预留大小、保留 `reserve_mib` 检查。compose 里 bot-api 容器改用 uid 10001 运行（与 tgdrive 相同，tgdrive 才能读取与删除），并每 10 分钟删除下载超过 1 小时的媒体文件（不动 `td.binlog`）。
- 自动封面：官方与自建服务接收的文件都经 `objects.put_object` 提交，沿用 `on_commit` → `ThumbnailService.enqueue`；视频优先内嵌封面，没有时自动截图，要求服务端有 FFmpeg。缓存不足时先等待新数据，文件写入满 10 分钟后由空闲补图接管并从存储读取，不需要用户再次预览；具体约束见 [media.md](media.md)。
- 下载提醒：`OfflineDownloads.on_finished(row)` 在任务完成或失败（`_run` 的 finally）时调用 `offline_finished`，绑定且开启提醒（`notify`）的私聊收到消息；私密空间的任务不显示文件名与路径；对外地址是 https 时附「打开文件夹／查看离线下载」按钮。
- 机器人头像与介绍图：`web/assets/telegram-bot-avatar.svg`（1024×1024，BotFather `/setuserpic`）与 `telegram-bot-description.svg`（必须 640×360，`/setdescriptionpic`），用 Chrome headless 截图生成同名 PNG。
- 回归：`tests/test_telegram_bot.py`（假 Telegram 客户端，含绑定、保存文件、建离线任务、提醒、HTTP 接口与审计、助手回复与确认按钮）。

## 收藏夹（文件星标，`objects.starred_at`）

- 界面统一叫「收藏夹」「收藏／取消收藏」；代码标识（`star`、`starred_at`、`/star`、`/starred`、`?view=starred`）与注释里的「星标」保持不变。侧栏的「常用文件夹」分组（代码里叫收藏，`favorites.py`）是固定的文件夹，是另一回事。

- 星标是对象行上的时间戳：移动、改名、移入回收站与还原随行保留（都是 `UPDATE key`），`_commit_blob` 覆盖写入沿用旧值，复制、转存、`link_copy` 不继承。只能给普通空间的文件加（不含文件夹、私密空间、系统区）。`POST /api/user/v1/star {paths, starred}`（`ObjectService.set_starred`，一次 ≤1000）；`GET /starred`（`UserApi.starred`，按 `starred_at DESC, key` 键集分页，`objects_starred` 部分索引，支持 `q`、`kind`）。网页对象 JSON 在有星标时带 `starred_at`。
- 前端：侧栏「文件 → 星标」（`?view=starred`，`library.tsx` 的 `StarredView`，按加星标日期分组，行尾实心星取消并可撤销）；文件菜单「加星标／取消星标」、多选菜单与选择栏、快捷键 `*`（所选或焦点文件，私密空间不处理）；列表文件名后、网格缩略图左下角显示实心星（`--star` 令牌）。回归 `tests/test_stars_playlists.py`。

## 音乐歌单（`playlists.py`，`playlists`／`playlist_items`）

- 条目按 (存储桶, 键) 引用普通空间的音频文件（`kind_of == "audio"`），每个账号 ≤200 个歌单、每个歌单 ≤5000 首。`objects` 上的触发器 `playlist_items_follow`（`AFTER UPDATE OF key`）让条目跟随移动；移入回收站的歌曲不列出、还原后回到原位；永久删除后条目留存但 JOIN 不到对象而不列出。位置是连续整数，移动一首时整体重排。
- 歌单分享（schema v42 的 `playlists.share_*`）：`POST /api/user/v1/playlists/{id}/share`（`enabled`、`expires_at`、`password`，以及默认关闭的 `download`、`save`；关闭时清除令牌与设置，再开得到新链接；密码哈希走 `password_work`；审计只记开关与是否设密码）。访客页 `/m/<令牌>`（`web/src/playlist-share.tsx`），公开接口在 `/api/public/v1/playlists/<令牌>`：歌单 JSON 的歌曲只有 `id`（`Playlists.item_id`＝令牌与键的 SHA-256 前 20 位）、文件名与标签，不含路径；`/unlock` 签发的访问凭证按 `playlist:<令牌>` 计算，与文件分享不互通；`/items/<id>/content`（`download=1` 需开启下载）、`?thumbnail=`、`/items/<id>/assets` 与 `/assets/<序号>`（同名歌词、字幕附件，不暴露路径）、`/avatar` 都每次按当前歌单内容校验（`_shared_playlist`、`_playlist_media`）。登录访客 `POST /api/user/v1/playlist-shares/<令牌>/save` 用 `link_copy` 引用到自己的文件夹（需开启保存，自己的分享返回 400），`/status` 只回答是否为自己的分享。预览窗口的 `downloadUrl` 为空时不显示下载。回归 `tests/test_stars_playlists.py` 的 `PlaylistShareTests`。
- 接口：`GET/POST /api/user/v1/playlists`、`GET /playlists/{id}?cursor=`（游标是位置）、`POST /playlists/{id}`（`name`／`add`／`remove`／`move:{path,before}` 可同时给出）、`POST /playlists/{id}/delete`、`POST /playlists/containing`。只在普通空间路由提供（私密路由白名单不含）。`UserApi.playlists` 惰性创建（部分测试用 `SimpleNamespace` 代替对象服务）。
- 前端：音乐页「专辑／歌单」标签（`?view=music&tab=playlists`，打开歌单 `?view=music&playlist=<id>`；`location.prefix` 为 `playlists`／`playlist:<id>`），歌单页可全部播放、随机播放、重命名、删除，曲目菜单有移到最前、上移、下移、添加到歌单、打开所在文件夹、从歌单移除。歌单页「添加歌曲」是 `SongPickerDialog`（`library?view=music&q=` 分页，多选后一次 `add`）；专辑、搜索结果与歌单页的曲目用 `useTrackSelection` 多选、`TrackSelectionBar` 批量加入或移除；曲目行的所在歌单标记来自 `usePlaylistMembership`（读全部歌单名称 + `/playlists/containing` 每批 500 首），任何改动调用 `playlistsChanged()` 广播 `tessera:playlists-changed` 让各列表刷新。「添加到歌单」对话框在 `user/playlists.tsx`（不导入 library.tsx，避免循环依赖），专辑页、搜索结果、文件菜单与多选（音频）共用。回归 `tests/test_stars_playlists.py`。
