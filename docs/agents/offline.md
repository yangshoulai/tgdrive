# 离线下载

给 AI 代理的模块细则（由根目录 AGENTS.md 索引）。队列、访问密钥创建任务、封面与保存位置、多连接、诊断、保存位置与优先级、出站请求、视频封装。

- 离线队列不设每账号未完成任务上限（原 `MAX_PENDING_TASKS` 已删除），同名检查用 `offline/service.py` 的 `_PendingKeys` 按需逐个查询（`offline_by_key` 索引），不要改回读出全部未完成任务的路径；网页与访问密钥的单次解析／创建由 `MAX_CREATE_ITEMS`（1000）限制；创建保留整批校验与事务。助手按 `actions.DOWNLOAD_BATCH` 自动分批入队并检查进度、取消与授权，不向模型暴露内部批次，不提高实际下载并发。浏览器工具作用于私密空间（`area=private` 或 `私密:/` 路径）时只有私密目录与私密回收站两个页面（后端 `PRIVATE_VIEWS`，前端 `executeClientTool` 也拒绝），锁定时前端拒绝私密导航；隐藏抽屉拒绝新的 `client_call`。
- 访问密钥创建离线任务（`KeyApi.download_owner`／`download_scope` + `OfflineDownloads.create(key_scope=...)`）：只接受属于用户的密钥，任务归该用户、写入其存储桶，普通接口的保存目录必须在密钥的读写授权前缀内，不能写入私密空间；脚本专用 `/api/v1/private/downloads` 需所属用户根目录 rw 密钥、脚本安装标识与有效短期私密授权，创建时传入 `private_scope`，状态查询 `status_of(..., private_scope=...)` 只返回该用户已授权的私密任务、且不续期；私密任务不依赖网页解锁（与缩略图后台任务一样用系统密钥写入，`_task_scope` 只复核账号可用），锁定后照常下载、重启后自动继续，停止／继续／重新下载／删除都不需要解锁；创建到私密目录、查看名称与来源、「更新下载参数」仍需当前会话已解锁；审计记为 `download.create`、操作者类型 `key`。
- 离线任务的缩略图（封面）与保存位置：网页在创建任务后 `POST /downloads/<id>/cover`（浏览器缩放好的 thumb/grid/poster，base64），`OfflineDownloads.set_cover` 把它们暂存为系统区对象 `.tgdrive/offline-covers/<任务>/<规格>`（计入配额，不写进数据库，也不会被当作媒体生成缩略图），任务已完成时直接设置；文件助手（`propose_downloads` 的 `thumbnail`／`thumbnails`）与访问密钥 API 在创建条目里带 `cover: {url}`，记在加密来源参数里。`_finish` 后台调度 `_apply_cover`：优先暂存图片，否则 `ThumbnailService.fetch_image` + `render_image`（FFmpeg 从本地临时文件缩放，没有 FFmpeg 时跳过），经 `apply_custom` 取消自动任务后保存；封面只用一次，失败不影响任务。删除任务时清理暂存。注意下载循环会整体重写来源参数，创建后提交的封面不能写进来源参数。保存位置：`create` 在同一事务里把本次目录记到 settings `offline.destination.<用户>`（普通、私密分开，`area` 为最近一次），`last_destination` 只在私密授权有效时返回私密目录；网页新建任务默认用它，旧脚本转交的私密任务解锁后用记住的私密目录；新脚本使用面板选择并记住的私密相对目录直接提交。回归 `tests/test_offline_covers.py`。
- 离线下载的多连接（`tests/test_offline_connections.py`、`test_offline_hls.py` 的 `test_multiple_connections_prefetch_segments_in_order`）：`download_connections`（1–8，默认 4，内存不足 1 GiB 时最多 2；`effective` 的每任务内存估算 `DOWNLOAD_MEMORY + (连接数 − 1) × CONNECTION_MEMORY`，32 MiB 来自实测，改流程后重测）由 `OfflineDownloads._connections()` 取用。共用 `offline/parallel.py` 的 `ordered(items, fetch, concurrency)`：最多 concurrency 个并行、按顺序交出、关闭时取消未完成的读取。直链：`_parallel_ok`（GET、200、大小已知且超过 16 MiB、`Accept-Ranges: bytes`、不在 `_single`）时 `state["ranges"]=True`，`_parallel` 按 `PART_SIZE` 切段，首段沿用已打开的响应，其余 `_range_part` 各开连接（核对 206、范围、总长、ETag，`PART_RETRIES` 次原地重试，失败的读取从进度里减回），每段先拼成一整段再 `upload_part(..., buffered=True)`；中断后 `_parts_valid` 通过且有 ETag 时只补缺的分段。来源不按请求返回范围抛 `_RangeRefused` → `_http` 清掉分段、记入 `_single`、单连接从头下载。分片 MP4 仍走单连接的 `_stage_video`。YouTube：`track_stream(connections=)` 读完第一段知道总长度后其余分段经 `_read_range` 并行（每条轨预读 ≤ `PREFETCH_BYTES` 64 MiB），`merge_tracks` 两条轨同时下载（预算按两轨合计）。M3U8：`_pipe_remux` 用 `_segment_bytes` 预读分片、`_HlsRelay` 用 `_prefetch_after`／`_buffer` 预读同一列表的后续资源，超过 `SEGMENT_BUFFER`（16 MiB）或未声明长度时照旧流式转发；密钥不预读。离线下载的分段写入（已在内存中）用 `upload_part(..., buffered=True)`，不占文件读取名额，只受上传名额 `upload_slots` 约束。
- 离线下载诊断（`offline/diagnostics.py`、`GET /api/user/v1/downloads/<id>/diagnose`、网页 `downloads.tsx` 的 `DownloadDiagnosisDialog`）：`_run` 为任务设置 `diagnostics.CURRENT`（ContextVar，子任务继承），`SafeHttpClient.open` 只在有记录器时登记连接（请求范围、状态、收到字节、首字节与空闲时间），`_write_part` 登记分段写入；只记字节数、状态、范围与时间，不记地址、请求头、文件名或内容，任务结束即移除。诊断入口由「下载与资源」的 `diagnostics` 开关（默认开启，经 `/upload-config` 下发，`api.diagnosticsEnabled`）控制，关闭时接口返回 400。
- 离线任务的「更改保存位置」与「立即下载」（`tests/test_offline_priority.py`）：`OfflineDownloads.relocate`（`POST /downloads/move`，ids 1–100）只改未完成任务的目录、文件名不变，在一个事务里同时改 `offline_tasks.key` 与未提交的 `uploads.key`，运行中的任务不中断（目标路径只在 `_begin`／`_finish` 读取最新值，新增读取路径时也必须读最新行）；普通与私密任务不能互相改到对方区域，私密目录需解锁。`prioritize`（`GET /downloads/<id>/now` 预览、`POST` 执行）给排队／等待恢复／停止／失败的任务设 `priority = 最大值 + 1`（schema v33，`offline_priority` 部分索引），调度器先取 `priority>0` 的任务再按 id；没有空位（或独占的 M3U8／YouTube 已在运行）时 `_yield_plan` 只从同一用户运行中的非 POST 任务里选进度最小的一个，`_yield_slot` 把它放回 queued（不是 stopped），不会暂停其他用户的任务；必须先释放该任务的操作锁再让出（调度器跳过持锁任务，否则空位会被刚暂停的任务占回）。手动停止清零 priority。
- 离线下载的所有出站请求（直链、M3U8、平台解析子进程、媒体轨）必须经 `offline/http.py` 的 `SafeHttpClient`，不要另开 socket 或让解析库自行联网：直连时它固定公网 IP，配置出站代理（`ResourceSettings` 的 `proxy`）时改由 `proxied_host` 拦截内网字面地址与内部主机名。连接阶段的网络抖动（含 DNS 查询失败）抛 `TransientError`（可重试），内容、认证、证书错误用普通 `DownloadError`。M3U8 的封装状态无法从中间恢复，任务级重试会从头下载，所以 `hls.py` 对单个分片（管道 `stream_one`、预读 `_segment_bytes`、回环 `_buffer`／`send_asset`）遇到 `TransientError` 按 `SEGMENT_RETRY_DELAYS` 原地重试，中途断开时重新请求并跳过已交给 FFmpeg 的字节（长度变化则失败），预读作废的字节从进度里减回；测试里把间隔 patch 成 0。`_run` 兜底的未知异常不写异常信息（可能含 URL），只把类型与 `_where` 给出的本项目代码位置写进日志与任务错误；配额不足（`QuotaExceededError`）指账号存储桶配额而非磁盘，`_quota_message` 在失败信息里给出配额、已用（含回收站与封面）与本文件已写入量。YouTube 媒体必须按 `track["chunk"]` 分段读取（`platforms.track_stream`），否则会被 googlevideo 限速。代理密码不得出现在审计、接口回显（用 `mask_proxy`）或错误信息中。解析直链时的文件信息探测（`_parse_request` 的 `probe`）每次最多 `PROBE_TIMEOUT`（10 秒），超时或 `TransientError` 时间隔 `PROBE_RETRY_DELAY` 重试，最多 `PROBE_ATTEMPTS` 次、总计 `PROBE_BUDGET`（24 秒）；所有用户共用的同时解析数是 `_parse_slots`（`Limiter`，每次解析时按「下载与资源」的 `parse_concurrency` 调整，1–16、默认 6）。批量解析 `OfflineDownloads.parse_batch`（`/api/v1/downloads/parse-batch`，1–`PARSE_BATCH_MAX`=50 项，每项等同一次 `parse`）逐项返回 `candidates` 或 `error`，`Paused` 仍让整个请求失败；整个请求最多 `PARSE_BATCH_BUDGET`（90 秒），未完成的项取消并返回 `retry: true`（脚本的批量请求超时 150 秒），回归 `tests/test_offline_probe.py`。来源的 408/425/429/5xx 用 `status_error` 归为可重试，写入时 `WorkBusyError`（传输名额等待超时）与存储通道的 `TelegramError`（400 等拒绝，错误里带 Telegram 的代码与说明；`TelegramAuthError` 直接失败并提示检查存储通道）同样按 `RETRY_DELAYS` 自动重试，只有 `QuotaExceededError` 直接失败，任务层由 `OfflineDownloads._run` 自动重试；不要把临时故障当成“文件已变化”清理断点。平台任务复用 `platform_source.entry`，只有 `ExpiredMedia` 时才重新解析。下载任务列表（`OfflineDownloads.list`）按添加时间倒序、同一批（`create` 共用一个 `created_at`）按编号正序排列，游标仍是上一页最后一个任务的编号，按它的 `created_at` 键集续读（v37 索引 `offline_owner_time`），网页在名称下显示添加时间；列表只带去掉查询串的来源地址（`source`）与完成文件的缩略图状态（`file`，`_attach_files` 每页批量查询），不得加入请求头、Cookie 或查询串；移入回收站的成品保留内部关联供还原跟踪，但列表 key／搜索与重新下载使用删除前路径，`trashed` 时不附带 file，也不允许打开目录；私密回收站沿用私密任务授权。完整参数只经 `/downloads/<id>/source`（`command_text` 还原成可再解析的 curl）给任务所有者，私密任务需已解锁。批量操作 `batch` 逐项复用 `control` 的校验，继续时跳过 POST 任务。
- 离线下载的视频封装（M3U8 `hls.remux`、平台音视频合并 `platforms.merge_tracks`）由 FFmpeg 写管道输出分片 MP4（`empty_moov+delay_moov+frag_keyframe+default_base_moof`；`delay_moov` 不能省，否则 TS 来源的 AAC 在 moov 里缺少解码配置，Safari／iOS 认不出音轨、只播放约 2 秒）。分片 MP4 不能直接保存：即使带 sidx，Chrome 每次拖动进度都要扫描整个文件。`OfflineDownloads._stage_video` 用 `offline/mp4.py` 的 `Defragmenter` 边收边转成普通 MP4：丢弃 moof／mdat 头只转发音视频数据（从第 2 段起上传），记录每个样本的大小、时长、关键帧和位置；结束后生成完整 moov（stts／ctts／stss／stsz／stsc／stco 或 co64，修正 elst 与各级时长），与内存中暂留的开头 16 MB 数据合成第 1 段最后上传；数据超过 4 GB 时用 co64 与 64 位 mdat 头（`header` 直接选 co64，不能先按 stco 试算，否则 `array("I")` 溢出，回归 `tests/test_mp4_index.py`）。直链下载（`_http`，从头下载时）先用 `_peek` 读开头 64 KB，`mp4.is_fragmented` 判定为分片 MP4 就同样交给 `_stage_video`（回归 `tests/test_offline_fragmented.py`），已保存的文件不做转换。新增封装输出路径时必须经过 `_stage_video`，不要改用临时文件（磁盘小）；验证时用 AVFoundation（Safari 的媒体栈）和 Chrome 分别看时长、音轨与拖动读取量。

- 文件级元数据独立保存后，离线任务附带的自定义封面同样写 `.tgdrive/media/`，三种规格和配额规则不变；任务列表用 file_thumbnail_versions 批量读取文件级封面，不能只查 Blob 默认图。所有完成的上传仍经 on_commit 初始化字段和资源，编辑不重写下载成品。
- 自动重试（`OfflineDownloads._run`）：`RETRY_DELAYS` = 10 秒、30 秒、90 秒、5、10、20 分钟；本次运行有新进度（`_stats` 的 `received` 超过开始值或有完成的分段）时先清零计数，偶发抖动不会累计到失败。存储通道（`TelegramError`）写入失败时设置 `_storage_paused_until`，调度循环在此之前不启动新任务，避免故障期间队列逐个耗尽重试；用户手动继续、立即下载会清除暂停。
- 续传校验值：优先强 ETag；来源没有强 ETag 但有 IMF-fixdate 格式的 `Last-Modified` 且长度已知时，用它作为 `If-Range`（`_validator`／`_unchanged`），响应的修改时间、总长度与地址都一致才追加，否则清理断点。回归：`tests/test_offline.py` 的 `test_last_modified_resume_without_etag`。
- M3U8 分段续传：`hls.SegmentCache` 把一次读完整的源分片按「序号-地址哈希」存到 `offline-cache/hls-<任务>/`（先写 `.part` 再改名；中途重试过的分片与超大分片不缓存；磁盘剩余低于「下载与资源」的预留空间时不写）。目前只用于连续 TS 走管道的 `_pipe_remux`（单连接 `stream_one` 与多连接预读都先查缓存）；回环中转（加密、字节范围、fMP4、分离音轨）不缓存。封装与上传仍从头进行，只是不再重复从来源下载。
- 平台分离音视频轨按整条轨续传：`merge_tracks(resume_dir=offline-cache/tracks-<任务>)`，完整下载的轨写 `track-N.done`（身份 `track_identity`：直链里有 `itag` 时用 `itag`+`clen`，否则用去掉查询串的地址；加文件大小），重跑时身份与大小一致就复用。一条轨因来源错误失败时让另一条下完再报错（取消仍立即停止全部）。
- 续传缓存的清理：`OfflineDownloads._drop_segments` 在任务完成、失败、删除、重新开始或更新参数时删除 `hls-<任务>` 与 `tracks-<任务>`；`start()` 时 `_sweep_segments` 删掉已不在排队／运行／等待恢复／已暂停状态的任务目录（`clear_cache` 只清 `task-*`，续传目录可跨重启保留）。回归：`tests/test_offline_hls.py` 的 `test_segment_cache_resumes_without_redownloading`、`tests/test_offline_tracks_resume.py`。
