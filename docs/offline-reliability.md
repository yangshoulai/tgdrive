# 离线下载兼容性排查与修复

验证日期：2026-10-12 至 13 日。以下区分代码中已确认的缺陷、真实来源响应，以及尚未在生产服务器验证的条件。验证使用独立临时目录，没有打开或迁移用户的 `.local-data`。

## 为什么桌面下载器能用，服务器却失败

Tessera 使用的 YouTube 解析器也是 yt-dlp，但原适配器只接受它返回的一小部分格式。完整下载器能够处理的 HLS 被适配器丢弃，M3U8 解析器又主动拒绝常见的时间线跳变等标签，所以安装同一个解析库并不意味着获得了它的全部下载能力。

此外，桌面下载器使用用户电脑的网络出口，可能沿用本机代理、缓存或登录状态；服务器的 IP、地区和登录状态可能不同。YouTube Cookie 只证明账号登录，不等于用于播放请求的 PO Token。YouTube 还可能把媒体地址绑定到解析时的出口，代理将页面和 googlevideo 分流到不同出口时，解析成功也可能下载 403。不能仅凭桌面成功就认定服务器的 403 一定由 Cookie 格式造成。

2026-10-12 核对 PyPI 时，仓库锁定的 yt-dlp 2026.8.19、yt-dlp-ejs 0.8.0、gallery-dl 1.32.16 已是稳定版本。未为解决问题盲目更换版本；生产镜像实际安装的版本仍应在管理员「下载与资源」查看。

## 已确认的实现问题

### M3U8 主动拒绝常见点播结构

原实现遇到 `EXT-X-MAP`、`EXT-X-BYTERANGE` 或 `EXT-X-DISCONTINUITY` 就报“首版暂不支持”，也拒绝普通 AES-128 和独立音轨。这是程序的支持范围不足。

用户提供的来源：

```text
https://v6.wsyzym3u8.com/202311/10/eayYj5bS1R1/video/index.m3u8
```

来源返回主列表和一个点播子列表，包含 2,114 个分片、总时长约 4,226.67 秒，以及 233 次时间线跳变。该链接触发的具体限制是时间线跳变；截图中合并描述 fMP4／字节范围／跳变的提示不能说明它同时使用了这些格式。

现在支持 H.264／AAC 点播的 TS、fMP4 初始化分片、显式／隐式字节范围、时间线跳变、普通 AES-128 密钥与 IV／媒体序号、密钥轮换和独立音轨。字节范围必须返回正确的 206 与 Content-Range；密钥必须为 16 字节。直播、低延迟或缺失分片、DRM、SAMPLE-AES、变量替换和外置视频组仍明确拒绝。

普通连续 TS 保留管道传输。复杂列表通过 SafeHttpClient 流式获取输入分片、初始化文件和密钥，保存到权限受限的任务缓存，再生成只含本地文件名的 HLS 列表交给 FFmpeg。输入不能触发 FFmpeg 自行访问外部 URL，成品直接进入加密存储。直接 M3U8 的缓存受账号剩余配额与磁盘保留空间限制；YouTube HLS 还受平台单任务大小上限限制。中断、完成和异常退出后的重启都会清理临时缓存。

### YouTube 解析与下载的适配不足

用户已确认：导入 Cookie 后的 403 发生在点击「解析内容」时。因此，下面的媒体 HLS 回退不能直接作为这次 403 的根因或解决证据；必须先判断网页、播放 API、播放列表是否被拒绝。

提供的 YouTube 地址含 `list` 与 `start_radio` 参数；系统会按 `v=UoPRTkK5KG4` 归一为单视频地址。这次报错不是播放列表批量下载限制造成的。

原适配器调用 `extract_info(download=False)` 后仍进行默认格式选择。yt-dlp 对标记为 `__needs_testing` 的格式会提前试下载，即使不要求正式下载；这样，解析清晰度可能提前触发媒体认证、产生临时文件或因媒体 403 丢失可列举的格式。现在改为上游列举格式模式（`simulate=list_only`、`check_formats=False`），只请求解析所需的网页、API、播放器脚本和清晰度列表；实际媒体读取由选定后的任务负责。这是已确认的适配缺陷，但缺少那次服务器请求记录，不能断言用户的 403 就由该分支触发。

还修复了同源重定向时无条件删除认证头的问题：同源 301／302／303／307／308 保留 Cookie 与 API 认证头；跨来源仍移除认证头，并由 CookieJar 按目标域、路径和有效期重新选择 Cookie。真实 yt-dlp 回归验证登录 Cookie 与 SAPISID 认证头能通过受控通道到达播放 API，同源 307 后仍保留，登录头不会进入 googlevideo 播放列表请求。补充客户端返回 403 时，只要其他客户端提供可用格式，就保留解析结果；全部失败时保留固定 warning 分类，不再把具体失败吞成“无格式”。

原代码只保留 `protocol=http/https` 的非分片格式，丢弃 `m3u8_native`。上游的未登录和登录客户端不同：同一视频导入 Cookie 后，可用格式和播放证明要求可能改变。原实现也没有尝试支持 Cookie 的 Safari HLS 客户端；重新解析后仍可能选中被播放服务器拒绝的 HTTPS 格式。

现在保留可用的 HTTPS 和 HLS H.264／AAC 格式，在上游默认客户端之外尝试 Safari HLS。正常情况下优先 HTTPS；媒体返回 401／403／404／410 时重解析一次，对 YouTube 直连媒体优先选择同一清晰度的 HLS，不自动降低清晰度；仅音频选择也能优先使用 HLS 音轨。所有播放列表、密钥和分片仍经过相同的域名限制与 SafeHttpClient。跨平台 CDN 保留 User-Agent、Referer、Origin、Accept 等播放头，不把账号 Cookie 或认证头转发到 CDN。

这能解决适配器丢失可用格式的问题，但不能使平台未提供的 HLS、登录／地区限制或服务器出口封禁自动消失。本次没有用户的真实 Cookie，也没有连接生产服务器，无法证明生产环境的那次 403 已经消失。

### X 的终止异常掩盖了来源响应

gallery-dl 的 `AbortExtraction` 是终止控制异常，不能直接解释为网络失败或 Cookie 失效。两条报告链接：

```text
https://x.com/NaiBaiYingTao/status/2109610858251006109/video/1
https://x.com/DelphiaLea35937/status/2109286671716110469
```

实测均完成访客登录，GraphQL 返回 HTTP 200，但媒体结果是 `TweetTombstone` 占位对象，没有可供解析的帖子媒体。上游在读取作者字段时抛出 `AbortExtraction('Unavailable')`，原错误分类没有识别这种情况。不能从占位响应进一步确定帖子是已删除、受地区限制还是仅允许登录账号访问。

现在识别占位响应、AuthRequired、NSFW／受保护帖子、无效认证、请求频率和嵌套异常。主接口没有结果时，尝试 X 自己的 `cdn.syndication.twimg.com` 公开嵌入接口。它不是第三方解析网站；同样经过平台域限制和受控网络通道。两个报告链接在公开嵌入接口也没有返回媒体，所以仍提示媒体受限／不可用。公开 SpaceX 对照帖可正常解析。明确的登录或年龄限制会提示导入有权限账号的 Cookie。

只输出固定错误分类、异常类型、代码位置与受控请求阶段；原始异常、签名地址、响应正文、Cookie 和代理密码不进入界面或日志。

### X 登录解析的 TypeError（2026-10-13 补充）

更新后另有一条帖子在导入 Cookie 时返回 `TypeError`。服务器日志的最后两条请求均为 HTTP 200，堆栈止于 `extract_worker.fetch → emit → json.dumps`，没有帖子 API 请求。这是适配器自身的协议错误，不能据此归因于 Cookie 失效、帖子不可用或服务器出口限制。

gallery-dl 1.32.16 在登录解析时先读取 X 网页与脚本，再生成 `x-client-transaction-id`。这个请求头的值是 `bytes`，requests 可以接受，但原适配器直接把请求头列表放进 JSON，因而在发送帖子 API 前报 `Object of type bytes is not JSON serializable`。匿名流程不生成这个请求头，上一轮 X 访客验证没有覆盖此缺陷。

现在在子进程协议边界按 ASCII 转换字节类型的请求头名称，按 HTTP Latin-1 无损转换字节类型的值；保留交易 ID、登录 Cookie 和 CSRF 请求头。请求仍通过主进程的 SafeHttpClient 和原有域名、请求头校验，不让解析库自行联网，也不把登录凭据传给媒体 CDN。

新增回归使用真实 gallery-dl 和解析子进程，覆盖 cURL 中的 Cookie、带点域名与主机域名的 Netscape Cookie。原实现三种输入均复现与服务器一致的错误堆栈；修复后均可生成并转交交易 ID，以登录态请求 TweetDetail 并解析图片／视频。另验证字节请求头和请求体在 JSON 通道中保持原值。相关解析器、平台任务与 HTTP 下载共 41 项测试通过。

真实链接 `https://x.com/goodgirlpupu/status/2073414018522333246` 在本机代理出口使用用户提供的登录 Cookie 验证：X 网页、脚本和登录态 TweetDetail 均返回 HTTP 200，成功解析 1 个视频，读取媒体前 64 KiB 返回 HTTP 206。没有下载完整视频或重启生产服务器；服务器需更新到包含此修复的平台镜像后再验证其出口。用户凭据只在验证进程的内存和标准输入中传递，没有写入源码、测试、日志或提交。

### HTTP 直链与网络故障

HTTP 直链与平台页是两条路径：前者读取实际文件，后者需要站点解析器取得媒体地址。直链已有 HEAD 被拒绝时回退 GET、强 ETag／Range 续传、POST 不预先发送等处理，本次专项均通过。没有用户提供的独立失败直链，无法推断所有 HTTP 来源都存在同一个缺陷；普通网页也不能当作文件地址下载。直连会拒绝内网、保留地址与 Fake-IP，启用代理时走容器可访问的代理地址。

解析通道连接中断仍归类为可重试；API 暂时失败的 HTTP 408／425／429／5xx 保留可重试类别，进入队列的任务会自动恢复。认证拒绝与证书错误不按网络抖动无限重试。

## 部署到现有服务器

修改源码不会改变已运行的镜像。本报告的验证在本地完成，没有远程重启服务器。仓库推送 `v*` 标签后会自动构建并发布镜像；等待构建成功后可使用对应的 `-platform` 镜像，或从修复后的源码重建平台镜像，保留现有的数据挂载、环境变量和反向代理配置。

使用仓库 Docker Compose 时，在现有 `build` 中启用 `target: platform`，再执行：

```bash
docker compose build tgdrive
docker compose up -d --no-deps --no-build --pull never tgdrive
```

单独构建平台镜像也可以：

```bash
docker build --target platform -t tgdrive:platform .
```

在管理端确认 FFmpeg、yt-dlp、EJS、JavaScript 运行时和 gallery-dl 可用，并分别启用 M3U8、X、YouTube。服务器需要代理时，代理必须是容器可访问的地址；容器中的 `127.0.0.1` 不是宿主机代理。让 YouTube 和 googlevideo 使用同一稳定出口。先不带 Cookie 尝试公开视频；明确要求登录的内容，再导入有播放权限账号的有效 Cookie。已经失败的任务可重新下载；旧票据没有独立音轨信息时需重新解析。

若为本地 Python 安装，在服务器现有虚拟环境中从更新后的源码执行 `python -m pip install -e '.[platform]'`；在 `web` 目录重新构建前端后，用现有服务管理方式重启单进程应用。继续使用原数据目录与启动配置，不需要更换数据库或重建账号。

## 服务器上继续定位解析 403

失败日志 `platform_extract_failed` 带有 `stage=extract`，并记录最近最多 16 次请求的固定阶段、客户端类别、认证字段是否存在及 HTTP 状态。连接失败使用 `platform_source_failed`，状态为 `transient` 或 `source_error`。示例（字段都是固定分类，不包含实际凭据）：

```text
requests=webpage:other:cookie=1:auth=0:200;player_api:web_safari:cookie=1:auth=1:403
```

- `webpage` 就失败：还未到媒体下载，优先检查服务器／代理能否访问 YouTube 网页、Cookie 是否有效以及出口是否被要求验证。
- `player_api` 403：网页可访问，但播放 API 拒绝当前会话或客户端；`cookie=1`／`auth=1` 只证明字段已经转发，不证明账号 Cookie 当前有效。使用浏览器能播放该视频的同一账号，重新导出 Cookie，并确认代理出口稳定。
- `manifest` 403：平台返回了播放列表地址，但该地址不可访问；检查会话、地址有效期和解析／播放出口是否一致。
- `transient`：连接未取得完整响应，不应当作 HTTP 403 或 Cookie 失效。本次最新匿名探测在第一条 YouTube 网页 GET 就发生连接中断，没有响应状态码。

在服务器重现一次后，可执行 `docker compose logs --since=10m tgdrive` 查看这些固定诊断行，同时核对管理端组件版本。若更新后仍失败，服务器的这组记录能进一步确定具体阶段；本次没有生产服务器访问权或真实 Cookie，不能证明它的解析 403 已消失。Cookie 更新无法替代缺失的播放证明或修复服务器出口限制。
